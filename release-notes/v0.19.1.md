# You didn't say the magic word

Failed sign-ins now slow down and get logged, and the domain page shows what a
MANIFEST can configure instead of assuming you already know.

## New & Noteworthy

**Failed sign-ins now cost you something.**

Fluid's login page sits on the public internet for some of you. It had no bound
at all: you could guess a password as fast as you could send requests. Repeated
failures for the same name now earn a growing delay. One second, then two, then
four, up to eight. Past that you get a 429 with a `Retry-After` header. A
correct password clears the count right away.

The delay is keyed on the name you typed, whether or not an account by that
name exists. That's on purpose: if only real accounts got slower, the response
time would tell you which names exist.

Two settings if you want to tune it:

- `CRYSTALLINE_AUTH_LOGIN_FREE_ATTEMPTS`: how many failures are free (default 3).
- `CRYSTALLINE_AUTH_LOGIN_MAX_DELAY`: how far the delay may grow, in seconds
  (default 8). Set it to `0` to switch the throttle off.

Every failed sign-in is now logged with the account and the peer address, so
fail2ban or your log tooling has something to read. Nothing was logged before.
An attempt on a name that has no account is logged as unknown rather than
written out: that string is usually a password typed into the wrong field.

This does not replace a rate limit at your proxy. It bounds guessing against
one account. It does not bound one attempt each against a thousand accounts.

**The domain page shows what a MANIFEST can configure.**

You had to already know that a MANIFEST can declare provisioning folders or tag
aliases. If your domain didn't declare one, the page said "No aliases" and
nothing more. Every section that carries meaning now says what it's for and shows
an example you can save as it stands. If you may edit the MANIFEST, a button
drops that section into the editor with the cursor in it. Nothing is written
until you save.

An empty MANIFEST gets the same treatment, plus a button that starts a whole
one for you.

## Fixes

**The sidebar collapse button did nothing on a phone.** It was drawn at every
screen width, but a narrow screen has no rail to fold into, so tapping it did
nothing. It's hidden on narrow screens now, where the top bar's
own button opens and shuts the sidebar.

**The login screen still wore the old mark.** Everything else moved to the
lattice in September. The login card kept drawing the gem it replaced. It now
draws the same mark the top bar and the browser tab do.

**Starting the daemon right after a stop could fail.** A stopping daemon
removed its lock file a moment before it let go of the index database. A new
one started in that moment (during an upgrade or when an agent reconnected)
found the database still locked and quit with "File is locked by another
process". It now waits for the old one to let go, up to ten seconds.

**A network-bound daemon printed a setup token you could not use.** The
first-run token came from the bind address alone, so every restart printed a
fresh one, even on an instance that already had an admin. There was nothing to
spend it on: once the first account exists, the setup endpoint answers 410
Gone. The daemon now asks the accounts database first. You get a token on a
real first run and never again.

**A busy instance could hang a sign-in instead of answering.** Password checks
run four at a time to limit memory use, and a caller waited for a slot with no
limit. Four junk sign-ins could park every slot and real ones queued behind
them. A caller now waits ten seconds at most, then gets a 503 telling it to
come back.

## Breaking changes

None.

One behavior change worth naming: mistype your password four times in a row and
the fourth attempt takes about a second. That's the throttle, not a slow
server.
