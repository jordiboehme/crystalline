# There can be only one

An upgrade no longer leaves an old daemon holding your index, and Fluid stops
showing you answers from a version you already replaced.

## New & Noteworthy

**An old copy of Crystalline now refuses a newer index.**

The Claude Desktop extension brings its own copy of Crystalline. If you update
the command line tool but not the extension, the extension can start an older
daemon against an index that a newer version already upgraded. Up to now that
older daemon did not check the schema and ran anyway. From 0.19.2 on, a copy
that meets a newer index stops at the start and tells you why:

> this index was upgraded by a newer Crystalline (schema v16, this binary
> knows v15). This copy is out of date. If Claude Desktop runs Crystalline as
> an extension, install the current .mcpb over it; otherwise upgrade this
> binary.

This protects you from the next upgrade on. It can't change the copies you
already have: if you use the Desktop extension, install the 0.19.2 `.mcpb` over
it now.

## Fixes

**After an upgrade every command said the index was locked.** When a newer
client meets an older daemon, it asks the daemon to stop. The old daemon gave
up its record right away, but its process could stay alive for minutes (for
example while it finished a model download), and it kept the index locked the
whole time. Every new daemon failed on "File is locked by another process"
until you killed the process by hand. Two changes close this:

- A stopping daemon now ends its process within ten seconds, and it keeps its
  record until the index is free.
- A client that asked an older daemon to stop now waits until the process is
  gone. If it stays, the client ends it, but only after it checked that the
  process really is Crystalline. This also works on daemons from older
  versions.

**`crystalline doctor --fix` could delete a lock file that was in use.** When
a daemon held the lock but had not written its record yet, doctor read the
lock as stale and deleted it, and the socket next to it too. The next daemon
then took a fresh lock file, and two of them could think they owned the index.
Doctor now deletes these files only when nobody holds the lock.

**Fluid could keep showing a reply from the version you upgraded from.** Fluid
asks the daemon if a manifest or an engram changed. The daemon answered "no
change" when the text was the same, even when the reply had new fields since
the last version. So after an upgrade, a domain page could miss its
configuration boxes until you emptied the browser cache. The check now
includes the version, so the first visit after an upgrade always gets the new
reply.

**Formatting in the manifest boxes showed as raw text.** A When to Use or
Scope bullet with bold text or code showed its asterisks and backticks. It is
rendered now.

**"Last checked" on the Team sync card showed the last change.** A check that
found nothing new did not record its time. So a domain that was checked every
few minutes could say "17 hours ago". Every check counts now.

## Breaking changes

None.

If you use the Claude Desktop extension, update it together with the command
line tool. An extension that is older than your index now stops with a message
instead of fighting the new daemon.
