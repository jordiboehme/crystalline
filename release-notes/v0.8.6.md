## New & Noteworthy

**A Crystalline that cannot start now says so instead of disappearing.** When `crystalline mcp` finds the knowledge index owned by another instance it cannot reach - typically a Claude Desktop extension whose bundled binary is older than a daemon updated through Homebrew - the session no longer dies as "Server disconnected". It comes up degraded: initialize succeeds, a single `status` tool reports what happened, which versions are involved and the exact fix, and the instructions tell the model to relay it. For the extension that fix reads: download the latest `.mcpb` from this releases page and install it over the current one (Claude Desktop has no in-app update). Extensions from v0.8.5 and earlier still fail the old way against a newer daemon; this release is the cut-over.

**The MCP server introduces itself properly.** Client logs used to show the underlying protocol library's name and version at initialize; they now show `crystalline` and the real release version, on the daemon, embedded and HTTP paths alike.

**The Claude Desktop extension knows its channel.** The bundle manifest sets `CRYSTALLINE_CHANNEL=mcpb`, so degraded-startup guidance (and future update hints) can name the right update path for how Crystalline was installed.

## Fixes

- Dependency refresh: turso 0.7.0 plus clap, toml, uuid, globset and keyring patch updates.

## Breaking changes

- A terminal `crystalline mcp` startup failure now serves the degraded session and exits 0 when the client disconnects, instead of answering initialize with a JSON-RPC error and exiting non-zero. Anything scripting `crystalline mcp` and keying off that exit code should call the `status` tool instead.
