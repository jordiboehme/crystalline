# Déjà vu

A move now keeps every reference intact, a section edit no longer doubles its
heading, and an edit that breaks a MANIFEST says so right away.

## New & Noteworthy

**A move is a refactoring now.**

You reorganise a domain, and the permalinks stay where they were. So a
permalink and its folder slowly go apart, and a `build_context` glob on the
folder misses half of it. There was no clean way back: `move_engram` kept the
permalink, and nothing else could change it.

`move_engram` now takes a `permalink`:

- Leave it out: the permalink follows the move when it matched the old path.
  A permalink you chose on purpose stays.
- `"path"`: take it from the new path.
- `"keep"`: leave it as it is.
- Any other value: use that one.

A move to the same path is allowed when only the permalink changes. That is
how you repair an engram that already sits in the right folder.

And every move now updates every reference to the engram: links, relations
and `crystalline://` addresses, in every domain you can see. Before, only a
move to another domain did that. A link by title needs no update and keeps
working. The answer says how many references were updated, and Fluid's move
dialog offers the same choice.

In a domain that reviews changes, a moved draft keeps its permalink unless
you pass one. The review matches your draft to the team's engram by that
permalink.

For drift that happened outside a move (a file moved by hand, an older
reorganisation), the evolve sweep has a new finding, V109: the permalink
does not match the folder. It names the fix. If the permalink is different on
purpose, acknowledge it.

**An edit of a MANIFEST tells you when routing breaks.**

A MANIFEST is what every connecting agent reads to decide where to look. If
an edit leaves `## When to Use` empty, routing for that domain gets worse, and
nothing showed it. The checks existed, but only `validate` ran them. Now
`edit_engram` and `write_engram` on a `MANIFEST.md` return the findings of the
new text in their answer: a missing or empty `Scope` or `When to Use`, a
heading that appears twice and the rest of the MANIFEST checks. Nothing is
refused. The agent sees the problem while it can still fix it.

## Fixes

**`replace_section` could write a section's heading twice.** The operation
keeps the heading line and replaces what is under it. When the new content
started with the same heading, the section came out like this:

```markdown
## When to Use

## When to Use

- Route here in sessions with ...
```

The first one is the one the MANIFEST reader takes, and it was empty. So
routing lost its bullets, and the edit still looked successful. Now a repeated
heading at the start of the content is dropped, and the answer says it
happened. The same goes for `insert_after_section`. A different heading at the
start is kept, since that is how you add a subsection.

The tool description and the capture skill now say it too: the heading line
stays, send only the body.

**A capture titled "MANIFEST" could replace your MANIFEST.** On macOS and
Windows the file system ignores letter case, so `manifest.md` and
`MANIFEST.md` are the same file. `write_engram` with that title and
`overwrite` replaced the MANIFEST of a folder domain with an ordinary engram, and then
reported a permalink conflict as if nothing had happened. Now it is refused
before anything is written. A MANIFEST changes through `edit_engram`.

## Breaking changes

None.

Two behavior changes you may notice: `links_rewritten` in a move's answer now
counts on every move, not only on a move to another domain. And a move is
refused while somebody has the engram open in Fluid's editor and the move
would change its address.
