# Bigger on the inside

Crystalline now runs under a path, so it can share a host name with your other services. And you choose which domains of a server you take.

## New & Noteworthy

**Crystalline under a path.** Not every team gets its own host name for every tool. Until now a Crystalline server had to sit at the root of one. Now set `service.public_url` to the address with its path, for example `https://example.com/crystalline`, and point your reverse proxy at the daemon.

- The whole server works there: the web UI, sign-in with a password or single sign-on, OAuth for Claude.ai and other hosted clients, MCP over HTTP and `crystalline connect`.
- Your proxy may strip the path or pass it through. Both work.
- With OAuth on, forward the two documents at the host root as well (`/.well-known/oauth-protected-resource/crystalline` and `/.well-known/oauth-authorization-server/crystalline`). The deployment docs have the nginx and Caddy lines and a short check you can run from outside.
- Two Crystalline servers on one host under two paths are two servers: separate sessions in the browser and separate sources on a connected machine.
- The Fluid image takes `CRYSTALLINE_BASE_PATH=/crystalline`.
- A server at the root works exactly as before. So do your existing connections and their sign-ins.

**Choose a server's domains (#128).** A team server can offer thirty domains when you need three. And every one of them that is the same domain as a local copy hides that copy. Now pick them: `crystalline connect https://crystalline.acme.com --domains alpha,beta`. Your agent sees those two and nothing else from that server. A search does not ask the server about the others, and they hide none of your local copies.

- Connect again with `--domains` to change the list. A connect without it keeps the list, so a new sign-in never adds domains you did not ask for. `--all-domains` takes everything again.
- A listed name the server does not offer yet (no rights, or not created yet) stays on the list. `connect` and `crystalline doctor` tell you, and the domain shows up once the server offers it.
- Two servers offer the same domain? The one that lists it serves it. The domain keeps its name on your machine, and `connect` tells you it moved.
- Take a domain off the list and a local copy it hid comes back.
- `crystalline status` shows each server's list. For the server from `CRYSTALLINE_REMOTE_URL`, `CRYSTALLINE_REMOTE_DOMAINS=alpha,beta` sets it.

## Breaking changes

None. A few things behave differently:

- `crystalline connect` keeps the path of the address. `crystalline connect https://example.com/anything` used to connect to the root of `example.com`. Now it connects to a server under `/anything`. An address with a query, a fragment or a backslash is refused.
- `service.public_url` refuses a path it cannot serve, for example `https://example.com/.` or one with a backslash. Before, such a value quietly meant the root.
- Under a path, the session cookie is scoped to that path. At the root it stays `Path=/`.
- `crystalline status` prints one more line per server: the domains it takes.
- The Fluid image without `CRYSTALLINE_BASE_PATH`: a request for `/assets` without the slash now gets the web UI instead of a redirect.
