# Game over, man

Fluid keeps up now: when an agent changes something, the page you are reading shows it without a reload.

## New & Noteworthy

**Live page refresh.** Until now an agent could edit the engram you had open, and the reading page kept showing the old text until you reloaded it. That is the wrong way round for a tool where agents and humans work on the same knowledge. Now the page follows the change:

- The reading page updates in place and says who changed it ("Updated a moment ago by ada"). It keeps your scroll position as well as it can.
- A deleted engram shows the not-found page. An engram moved within its domain takes you to its new address.
- The sidebar, the folder tree, the listings, search and the badges refresh the same way.
- It works for every kind of change: an agent's edit, a save in the web editor, a file changed on disk, a discard, a share pull, a resync.
- On a shared install every session only hears about what it could read anyway. A draft only reaches its owner.
- Behind a reverse proxy, turn buffering off for `/api/`. Fluid keeps one event stream open, and a proxy that buffers it holds every change back. The bundled nginx config has the line; the deployment guide has the Caddy one.

Under the hood there is one event stream, `GET /api/v1/events`, shared by all Fluid tabs of a browser. If the connection drops, the browser reconnects and catches up on what it missed. If the server turns it away, Fluid checks that you are still signed in and tries again, waiting a little longer each time, and then refreshes what you see. No polling.

**Where did that come from?** Knowledge read in from a wiki or a repository now remembers where exactly it came from. Each engram an agent distils from a source carries `resource`: the page or the file it was read from, pinned to the commit for a git source. When an agent answers from such an engram, it gives you that link, so you can check the source yourself.

- `edit_engram` can now set `resource` and `source_version`, so a re-ingest moves them to the new version.
- `evolve_engrams` reports an ingested engram without a `resource` as V111. The agent asks you before it sets one, because a guessed source is worse than none.

**Small print.** Remember when a single 1.44 MB floppy disk was enough to ship software? This release has something extra on board, and it would still fit on that floppy. It even fits in 640 kB. No need to edit your CONFIG.SYS, load HIMEM.SYS for extended memory or run MEMMAKER first. Some things are found, not announced.

## Fixes

- A cross-domain link written with a domain's canonical name or an old name now shows as a link in Fluid.
- A link like `[[ops:Runbook]]` now stays unresolved when `ops` is not a registered domain, instead of pointing to an engram with the same title in your own domain. Links that 0.20.0 bound this way now show as broken.
- A link to an engram in another domain that does not exist yet now works as soon as that engram is written. The same goes for an edit, a save or a move that gives an engram that name, and for an engram the web editor puts back after it was deleted while you were editing it. Before, the link stayed broken until the domain that holds the link was written to or indexed again.
- The skills never said how to link to an engram in another domain, and one rule read as if it could not be done. They now say it: `[[domain:Title]]` for another domain, a bare `[[Title]]` only inside the same one. When a bare link is broken and the title exists in another domain, `crystalline verify` names that domain and the link to write.
- When `read_engram` or another tool that takes an identifier finds no engram, the error now names the permalink it probably meant. For example, `guides/Agent Workflow Guide` gets "Did you mean `guides/agent-workflow-guide`?"
- `write_engram` with overwrite now replaces the engram in its own file, also when the file is not named after the title (like `Code Review Standards.md`). Before, it wrote a second file, failed with "permalink already used" and the old text stayed. An engram that lives in another folder is refused with a hint to move it first.
- A new engram whose permalink already belongs to an engram in another folder is now refused, with a message that names that folder. Before, the tools offered to overwrite it.
- If 0.20.0 left such a second file behind, `crystalline doctor` now finds it. `crystalline doctor --fix` moves its text into the engram's own file and deletes the copy. If the engram changed after the copy was written, doctor only reports it: compare the two and delete the copy by hand.
- When a share was merged, Crystalline deleted its branch, and GitHub closed every pull request based on that branch. Now those pull requests are moved to the branch the share was merged into first. If a move fails, the branch stays and the sync status says which pull request is in the way. The next sync tries again.
- When you withdrew a share, or shared again after a share was declined, Crystalline deleted its branch, and GitHub closed every pull request based on that branch. Now the branch stays while an open pull request is based on it, and the sync status names that pull request. Crystalline does not move it, because that would change what it proposes. Once it is closed or moved, the next sync deletes the branch.
- A share branch also stays while another pull request comes from it, like a backport. Before, merging the share closed that pull request.
- If GitHub refuses to delete a share branch, for example because of a branch rule, the sync status now says so. Delete it by hand.
- When you and your team both added the same key to an engram's frontmatter (like `domain_name` in a MANIFEST), updating from the team could keep the key twice. The file did not parse any more and the domain lost its name and routing. Now the frontmatter is merged key by key, and a merge that would break a file becomes a conflict instead. `crystalline verify` reports a repeated key as `E010`, and `crystalline doctor --fix` removes the extra copy when both copies have the same value.
- A draft somebody shared with you can now be read by its title. Before, reading it by title gave you the team's page with the same title, not the draft.

## Changed behaviour

- A file whose frontmatter repeats a key is now reported as `E010` instead of `E001` by `crystalline verify`. If you silence `E001` in `.crystalline.yaml` or filter on it in CI, add `E010` too.
- A file path no longer opens a shared draft. Use its permalink or its title, like for every other engram.

## Breaking changes

None.
