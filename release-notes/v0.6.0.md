## New & Noteworthy

- **GitHub Copilot CLI joins the harness lineup.** `crystalline install copilot` wires the full integration in one idempotent command: MCP registration (driving the `copilot` binary and falling back to `gh copilot` when only the GitHub CLI form is installed), the SessionStart routing hook and Stop capture nudge in a dedicated `~/.copilot/hooks/crystalline.json` and the four topical skills in `~/.copilot/skills`. `--project` targets `.github/hooks` and `.github/skills` behind Copilot's folder trust, `COPILOT_HOME` is honored and `crystalline doctor` reports the new harness alongside the other two.
- **A routing prompt Copilot can hear.** Copilot parses a hook's stdout as one JSON document and drops plain text, so the new `crystalline prompt system --format copilot` wraps the routing prompt in the `additionalContext` envelope, stays silent on resumed sessions (which already carry the earlier routing block) and folds session-start auto-update notices into the envelope.
- **verify learns the identifier grammar.** New rule E008 warns when a frontmatter permalink starts with the domain's own name - permalinks are domain-relative and the domain name is per-user configuration - unless the file's own folder path explains the prefix.

## Fixes

- **Identifiers are taught consistently everywhere.** Agents kept gluing the domain onto the permalink and burning a failed call learning the bare form - taught to them by the tool schema itself. The parameter docs, tool descriptions, CLI help and skills now all agree: a bare permalink or title is domain-relative, `crystalline://domain/permalink` is the one absolute form (mirroring the `[[target]]` and `[[domain:target]]` wikilink pair), and a domain-prefixed miss now answers with the exact bare identifier to retry with, so a stumbling agent recovers in one step.

## Breaking changes

- A scheme-less `domain/permalink` composite identifier no longer resolves anywhere. It was previously accepted by `read_engram` when no `domain` argument was passed; use the bare permalink or the `crystalline://` URL instead.
