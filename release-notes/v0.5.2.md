## New & Noteworthy

- **Upgrades without the seance.** A newer crystalline notices an older daemon, asks it to leave gracefully and takes its place. Agent sessions ride through the swap: the MCP bridge reconnects, replays its handshake and carries on as if nothing happened - because as far as your agent is concerned, nothing did. `brew upgrade` and walk away.
- **Connect existing knowledge in place.** `domain add --origin` and the `add_domain` tool now adopt a non-empty folder or an already-registered domain instead of asking you to delete your own files first (a real request from a real Tuesday). Local files are never overwritten; whatever differs from the repository becomes an ordinary local change to share or update.
- **`status` tells the truth now.** One human-readable report whether or not a daemon runs (`--json` for machines), opening with whose view you are getting: the daemon (pid, version, uptime), a direct read because none is running or a direct read because you bypassed it. It also shows what the daemon is doing right now, the embedding backlog, domains registered but never indexed and when each team domain gets its next background poll.
- **A properly detached daemon.** Full session leader, no controlling terminal, spawned by whoever connects first and loyal to nobody. The lifecycle is documented in docs/deployment.md.

## Fixes

- The old daemon no longer outlives its own binary after an upgrade.
- MCP stdio bridges no longer die with the daemon; requests orphaned by a restart get a retryable error instead of eternal silence, and the bridge logs its reconnects to stderr where your harness can see them.
- `status` no longer prints surprise JSON when a daemon happens to be running, and no longer swears nothing is indexed while a daemon with a full index sits one socket away - it names the index it actually read and warns when a live daemon did not answer.

## Breaking changes

- The `status --json` shape changed: store fields are top level now (matching `ctl status`), plus a `registered` list and an `activity` block. If you parsed the old nested `store` object, update your jq.
