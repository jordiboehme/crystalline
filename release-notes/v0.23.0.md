# All for one, and one for all

Your agent can now use your own domains and your team's servers at the same time, through the one Crystalline it already talks to. A container can get its first admin from the environment, and an agent gets an account with a token instead of a password.

## New & Noteworthy

**Domains from shared servers.** Your notes live on your laptop. Your team's knowledge lives on a server, and maybe a second team runs another one. Until now your agent saw one of them. Run `crystalline connect https://your-server` once per server. You sign in through the browser (or paste a personal MCP token with `--token`), and from then on your agent sees your local domains and every server's domains side by side. Your harness setup and your hooks do not change.

- Every domain has one name on your machine. A name that is already taken gets the server's name as a suffix, for example `jordi-acme`, and `connect` tells you at once. A name never changes on its own later. `crystalline domain rename jordi-acme notes-acme --local` picks another one.
- The same team domain on your laptop and on a server is one domain. The server's copy is used while you are connected. Your local copy stays on disk untouched (no pull, no write, no share) and comes back when you disconnect. If it holds changes you have not shared, `connect` warns you.
- A call for one domain goes to its server only. A search over everything asks your laptop and every server at once and waits at most three seconds for each (`remote.deadline_ms`). A slow or offline server is left out and named in the answer.
- Live pages and draft links work on a server's domains. Your agent shows up by name in the participant strip of a page somebody has open there.
- Session start still works with a server down: its part of the routing block comes from a small cache, with one line saying it may be out of date. Nothing else of a server's knowledge is stored on your machine.
- `crystalline status` and `crystalline doctor` list every server: the account, the sign-in, whether it answers and which names it gave out. `crystalline disconnect acme` removes one and ends its sign-in on the server.
- The local web UI lists the domains from your servers, with a link to each server's own web UI.

**Offline is not an error.** A VPN that is not connected, a hotel network or a laptop that just woke up: a server can be out of reach at any time. Crystalline never gets stuck because of it.

- Every request to a server has an overall limit: 10 seconds for one domain, the three-second deadline for a search over everything.
- A network problem never asks you to sign in again. Your sign-in is kept, and the next call tries again.
- After a failure a server is skipped for 30 seconds, so your agent gets a quick answer ("cannot be reached right now (check the VPN or the network)") instead of waiting again. Nothing is queued for later.
- The first answer from the server clears it. No restart of the daemon or of your harness.
- A server that is only slow is not counted as down.

**The first admin from the environment (#126).** A fresh container used to need a look at its log before anybody could sign in. Set `CRYSTALLINE_ADMIN_NAME` and `CRYSTALLINE_ADMIN_PASSWORD_FILE` (a Docker secret) and the first start creates that admin. It happens only while the instance has no account, and a later start never changes it. The plain `CRYSTALLINE_ADMIN_PASSWORD` works too, but it shows up in `docker inspect`. The deployment docs have a compose example.

**An account per agent.** A deployed agent needs its own account and a token, not a password nobody types. `crystalline users add agent-build --role editor --mcp-token build-runner` creates the account without a password and prints its token (`--json` for scripts). The agent then connects with `CRYSTALLINE_REMOTE_URL` and `CRYSTALLINE_REMOTE_TOKEN`, no browser needed.

**For the people who run the servers.** Servers now answer `POST /api/v1/ctl` for connected machines. It always needs a token and serves six commands under the account's own rights. A private domain never shows up in an answer. `POST /api/v1/oauth/revoke` lets any OAuth client end its own grant; `disconnect` uses it. A connected machine does not follow redirects, so give it the server's exact address (https and the path the server answers on).

**Build and release.** The build no longer takes a commit to check out from its caller. It always builds the commit the run was started for.

## Fixes

**The advice for a possible contradiction led to the next finding.** For two lines that held at different times, `V302` said to close the older engram's validity window. The next sweep then reported that engram with `V001`, because it still read as current. Now the advice is to let the newer engram supersede the older one with its real end date.

**A backslash in a frontmatter field turned into something else.** In the web UI's frontmatter fields, a value like a Windows path (`C:\temp\new`) came back with a tab and a line break, and a value that ended in a backslash broke the frontmatter. Now the value is saved and shown as you typed it.

## Breaking changes

None.

- The index schema is unchanged, so 0.22.1 still opens it.
- Behaviour change you may notice: `crystalline connect --json github` must now be written `crystalline connect github --json`. With a flag before `github` the command now tells you so.
- `crystalline status --json` gains a `sources` field. No existing field changed.
