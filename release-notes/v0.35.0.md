# It's alive!

Reflection pages keep themselves current, agents get a name of their own and you can find and invite people. Administration moved to one place.

## New & Noteworthy

**Reflection pages that keep themselves current.** Some pages describe a state that moves: the architecture as it is now, what changed this week, the open risks. Until now such a page moved only when one of its own sources changed. Now a page can carry a freshness in its frontmatter, for example `freshness: 1d`. Any duration of one hour or more works. When it runs out, the next reflect run checks the page against its pact and brings it in line, also with engrams from the other domains the run may read. Nothing to do is fine: the run records the page as unchanged.

- Fluid shows when a page was last checked and when it is due again. A page that missed a whole period shows as overdue on the page, with a hint when the reflect loop runs less often than its freshness. A page that a run skipped also shows in `crystalline doctor` and the admin view.
- A page can have its own pact: `arch/overview.pact.md` next to `arch/overview.md`. It adds to `PACT.md` and never replaces it. Pages below it follow it too, and every page shows the chain it follows, for example "Follows: PACT.md > Architecture overview". Only curators write a pact file.
- A page can own the pages its prompt creates. Checking the owner checks the whole set: missing pages are created, the others updated and pages that are no longer needed retired.
- Retired is a status, as for engrams (`archived`). A retired page is hidden in the navigation behind a switch, stays reachable by link and search and can be restored by a curator. A page that already has a retired status word is hidden after the update too.
- A scheduled or agent run never deletes a page. It retires it. It also leaves the pact text and a page's freshness and follows to a curator: when feedback asks for such a change, the run answers in the thread.
- A retired page no longer covers its engrams. Engrams that only a retired page cites show as unreflected after the update.
- The new Reflection actions (`reconciled`, owner, retire and restore) and `reflect` with `stale` need a 0.35 server. An older server refuses them.
- The page settings live in a side panel on the page, like the one for engrams.
- A new Reflection page cannot be named like a Windows short name (`OVERVI~1.md`), because on Windows such a name can reach another file. A page that already has such a name stays.
- The reflect status says when the next page falls due (`next_stale_at`), also with `--no-counts`, and counts due pages as `stale`. The webhook trigger sends a due page right away, without waiting 30 quiet minutes.

**Agents with a name of their own.** A loop runner used to need a person's account. Now an admin creates an agent: `crystalline agents add scotty --loops reflect`. The agent gets a token (`cag_...`, 90 days by default, two live at a time) and reaches every domain of the instance for its loops, private ones too. It works only during a run: outside a lease its token reaches the automation steps and nothing else. Its writes show as `<client>-for-agent:scotty`, its commits as `Scotty (agent:scotty)`. Without a GitHub App, the commits use the noreply address of the account behind the instance credential, so GitHub credits that account. Agents need `auth.mcp` on. The server reads that setting once at start, so a change needs a restart. `crystalline doctor`, `crystalline <loop> status` and `run` warn 14 days before an agent's token expires. Administration > Agents shows it in Fluid.

- `crystalline reflect run` and `evolve run` send the new header `X-Crystalline-Run-Loop`. It binds the session to one loop, so an agent with both loops never mixes two pull requests.
- An agent may take at most 30 leases in 10 minutes, and only when something is due for its loop on that domain.
- A runner uses the agent's token in `CRYSTALLINE_REMOTE_TOKEN`, next to `CRYSTALLINE_REMOTE_URL`. `crystalline connect` does not take an agent token. People accounts that run a loop today keep working: nothing is converted. To move one to an agent, create the agent, put its token in `CRYSTALLINE_REMOTE_TOKEN` and remove the old account.

**Invite people with a link.** An admin creates an invite link for a role, and if wanted for a domain and a level. The link is shown to copy, never mailed. It is used once and ends after 7 days by default (30 at most). Opening it shows who invited you and to what. Nothing happens until you confirm. On an instance with single sign-on the link signs you in through it, and after that you land on the invited domain. An existing account only gets the membership. Owners and managers of a private domain may invite into their domain when an admin turns on `auth.invites.managers`.

**Find people.** The Members card has a people picker instead of a field for the login name. It searches login and display name from two letters on. Admins can also search by a full email address. When nobody matches, the picker offers to invite someone new.

**Administration.** Users, Agents, Invites and the GitHub connection live under `/admin` now, with General for the version, updates and the address. `/users` and `/settings/github` forward to their new place. `/admin` and `/invite` are reserved now: a `service.public_url` whose path starts with one of them is refused, and the daemon warns and serves at the root. The users table is made for hundreds of accounts: search, filters, sort on every column and pages, all kept in the URL. One account is edited in a side panel. Deactivate, reactivate and change the role for a whole selection at once. The list of domains an account may write can now be set in Fluid too, and with `PUT /api/v1/users/<name>/writes`.

**The domain sidebar.** Drag its edge to make it wider (200 to 480 px). Double click resets it, and dragging it very small folds it to the rail. A lock marks a private domain, and a second mark a domain with a Reflection.

**Tentative knowledge is named.** An engram with the status draft, proposed, idea, poc or open is not decided yet. Agents now see that status in `build_context` and in a Reflection's sources, and they are told how to treat it: say when an answer, a spec or a plan builds on it and let you choose. Building on it is fine. A plan that does names it, for example "assumes the proposal X", so it can be checked again once X is decided. `open` is new as a tentative status: such engrams leave the contradiction check, like drafts. The reflect prompt changed with this release, so its checksum changed too.

**A cheap status for frequent polls.** `automation_status` takes `counts: false` (`crystalline <loop> status --no-counts`). It answers if a run is going, the last run and where the loop runs, and skips counting what is due.

## Fixes

- `automation_status` slowed down for a part of every five minutes on a server with a GitHub App and many team domains. A call could wait for GitHub up to 10 seconds. Crystalline now asks GitHub in the background before its cached answer ends. The status also reads through the read connections and no longer waits for writes. The periodic jobs, the GitHub lookups and the status calls log how long they took (`crystalline_engine::timing`, at INFO from one second). Thanks to tomek-pv for the report and the timing data. (#239)
- Hosted ChatGPT showed a successful `read_engram` as `{}`. Over MCP, `read_engram` now returns the engram text in `markdown` instead of `content`. Nested `content` keys, such as an observation's, stay. The CLI and the REST API are unchanged. Thanks to truepele for the report and the investigation. (#237)

## Breaking changes

- PostgreSQL: a 0.34 binary refuses a database that 0.35 has used, because of the new tables for agents and invites. A 0.34 standby refuses after the first 0.35 takeover, so update all instances together. docs/deployment.md says how to go back.
- The index keeps when each Reflection page was last checked and which engrams it covered. After the update an older binary refuses the index, on Turso and on PostgreSQL, and its `reindex --wipe` refuses too. docs/deployment.md says how to go back. A `reindex --wipe` on 0.35 forgets which engrams the pages covered: they show as unreflected once.
- An older binary that saves a Reflection page drops the page's owner and retired record. The status word stays.
