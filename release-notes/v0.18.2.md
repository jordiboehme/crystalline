A patch for Claude Desktop on Windows. If Claude Desktop stopped launching, or the Crystalline extension refused to update, this is for you.

## New & Noteworthy

**The Claude Desktop extension's daemon no longer outlives Claude Desktop.** Desktop runs extensions in place, so the background daemon the extension started was running from inside Claude Desktop's own extension folder, and it was built to outlive its clients (that's the point of a shared daemon). On Windows a running executable is locked, and Claude Desktop is a packaged app. Result: a daemon that stuck around after Desktop quit kept the extension's binary locked, blocked the extension from updating, and could stop Claude Desktop from starting at all. From this release the extension's daemon stays attached to Desktop and exits on its own five seconds after its last client disconnects. Nothing survives Desktop's exit for longer than a moment, and the web UI and file watcher keep working while Desktop is open. Every other install (Claude Code, Codex, `crystalline serve`, containers) keeps the daemon it had: shared, always on, outliving its clients.

`crystalline status` shows the bounded life as a `Lifetime:` line, and `ctl status --json` carries it as `idle_exit_secs`. A browser tab on the web UI doesn't count as a client; run `crystalline serve` if you want the UI without Desktop.

## Upgrading on Windows from 0.18.1 or earlier

The fix can't install itself over a running 0.18.1 daemon: that daemon holds the very file the new extension has to replace. Clear it once. It won't come back.

1. Quit Claude Desktop. Fully: check the system tray.
2. Check for the leftover process, in PowerShell:
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='crystalline.exe'" | Select-Object ProcessId, CommandLine
   ```
   A leftover daemon shows `serve --daemon` in its command line.
3. Stop it:
   ```powershell
   Stop-Process -Name crystalline -Force
   ```
   Or Task Manager, Details tab, `crystalline.exe`, End task. There may be more than one.
4. Install the 0.18.2 extension, then start Claude Desktop.
5. Confirm: quit Claude Desktop, wait ten seconds, run the command from step 2 again. From 0.18.2 on it returns nothing.

If Claude Desktop is refusing to start right now, steps 1 to 3 are the fix: it starts once the leftover process is gone.

macOS users: an older extension leaves a harmless stray `crystalline serve --daemon` behind after Desktop quits. `crystalline ctl shutdown` ends it, or just install 0.18.2 and quit Desktop once. Self-destruct sequence: armed, and this time it completes.

## Fixes

- Claude Desktop on Windows could fail to launch, or the Crystalline extension could fail to update, after the extension had run: a background daemon started from inside Desktop's extension folder outlived Desktop and kept its binary locked. The extension's daemon now exits five seconds after its last client leaves.

## Breaking changes

None. One behaviour change worth knowing: a daemon started by the Claude Desktop extension no longer stays up after Desktop quits, so a Claude Code session that was sharing it reconnects and starts its own (the reconnect is automatic; the session keeps going).
