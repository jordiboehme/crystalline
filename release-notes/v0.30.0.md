# You shall not pass!

Access to team domains follows GitHub, and knowledge only goes where its readers may follow.

## New & Noteworthy

**A GitHub App of your own.** Until now a team server reached GitHub with one person's sign-in. That person's access was everybody's access, and when they left, the server lost its way into the repositories. Now a team server can use a GitHub App of its own. It reads, pulls and shares with its own token for each repository.

- Create it in Fluid: GitHub settings, Create GitHub App. GitHub asks you to confirm, then Crystalline stores the App and offers Install on repositories. This works with GitHub Enterprise Server too.
- Or bring an App you already have: `crystalline github app set`, or the `CRYSTALLINE_GITHUB_APP_*` variables for infrastructure as code (with `_FILE` forms for Docker and Kubernetes secrets). The variables win over a stored App.
- Commits name the person as author and the App as committer.
- `crystalline doctor` checks the App: the key, the clock, the installations and its four permissions.

**Access follows GitHub.** With an App, who may read and write a team domain is what GitHub says about its repository. You manage it in one place.

- Sign-in stays where it is (for example single sign-on with Entra ID). Each person links their GitHub account once: on their profile in Fluid, from a link their agent hands them, or with `crystalline connect github --personal`.
- GitHub write or more means write in Crystalline. GitHub read means read.
- A domain is shared (everyone signed in reads) or private (only people with read on GitHub). Connecting a team domain asks which one. Nobody opens a confidential repository by accident.
- Roles are cached for five minutes. When GitHub can't be reached, the last known role holds for one more hour.
- Webhooks bring changes on GitHub in within seconds, like a déjà vu that tells you something changed. A webhook can only narrow access, never widen it.
- A domain whose repository lost the App, was deleted or moved to another owner is closed (admins only) until an admin reconnects it. The admin banner and `crystalline doctor` say why.
- The Members card shows the people on GitHub to those who may write. Changing members by hand on such a domain is refused: change it on GitHub.

**The Reflection stays open.** Not everybody who should read or comment on a Reflection has GitHub access. A manager can now add Reflection collaborators per domain (`crystalline domain members <domain> reflection add`, or the Members card). They get the Reflection, never the engrams.

**Share on purpose.** A Reflection page in a shared domain may now draw on a domain fewer people may read, but only when a person says so. The agent asks you first and shows what it would share. One yes counts per person, page and source domain until the page's readers widen. The source's name stays hidden from readers who may not read it.

**Unattended runs stay in their lane.** A scheduled reflect or evolve run reads only domains whose readers cover the domain it works on, and writes only into that domain. So a question in a shared thread can't make an unattended agent answer from your private domains. Jedi mind tricks don't work on it.

**One evolve runner per team domain.** When several clones of a team domain scheduled evolve, each opened its own pull request. Life finds a way, but one way is enough. Now the instance that schedules it claims the domain (`evolve_home` in the MANIFEST), and the others refuse a scheduled run and name the home.

**Team repositories guard themselves.** A clone of a team repository, registered as a plain local domain, could switch the Reflection on and push its pages with git. Crystalline now refuses that and says how to connect the domain instead. The GitHub Action can check a team repository for a `reflections/` folder that does not belong there: set its `team-repository` input to true (it runs `crystalline verify --team-repository`).

**Missing files are named.** `crystalline verify` warns about a link to a file the domain does not have.

## Fixes

- A Reflection page could carry text drawn from a domain fewer people may read, and so hand it to every reader of the page and of its backup branch. Such a source is now refused, unless a person shares it on purpose. Pages written before are flagged in the queue, and the backup holds them back.
- Inside Claude Desktop on Windows, searches could find no domains while the routing block listed all of them. The Claude Desktop app package turned out to be bigger on the inside: commands started there wrote to a private copy of Crystalline's folder that the daemon never reads. They now send their writes to the daemon, or refuse and point to a terminal. `crystalline doctor` and `crystalline status` name a split state. Run `crystalline doctor --fix --merge-desktop-state` once, from a terminal outside Claude Desktop, to bring it back together.
- Moving an engram to another domain left its own links dead: a bare `[[link]]` now pointed into the new domain. Those links get the old domain's prefix now, links into the new domain lose theirs, and the move names any link that still does not resolve (`links_dead`).
- An MCP message over 16 MiB on stdio made the client wait forever. It gets an error answer now.
- On Windows, a command that started the daemon could keep the program that ran it waiting until the daemon stopped (the daemon held on to the command's output). It lets go now.

## Changes

- Domains connected before 0.30.0 learn their repository's and owner's ids on the first lookup through the App. A transfer before that lookup is not noticed. Keep the origin state folder (in a container, the `/data` volume) across restarts.
- With an App, a person's own GitHub sign-in by token or OAuth is refused. Their older token keeps working for their shares until they link through the App.
- With an App, the MCP open tier acts as `github.agent_identity` on GitHub domains, at most as an editor.
- The Reflection backup branch no longer carries the hidden `.reflected/` folder. After a restore, the restored pages are the new starting point, and feedback that was open before the restore is gone.
- GitHub Enterprise Server was tested against a simulated server, not a real one. Please tell us how it goes.
- An archive import skips a file whose name Windows can't hold (like `CON.md` or a name that ends in a dot) on every system, so a domain never carries a file a Windows teammate can't check out. The import report names it.
- A sign-in through single sign-on no longer takes an email address the provider marks as not verified.
- A move no longer rewrites links in domains you may only read. Those engrams are named in `links_failed`, so somebody who may write there can fix them.
- Every dependency is on its latest version, among them rmcp 3.8.0. Fluid builds need pnpm 12.16.0.

## Breaking changes

- The environment variable suffix `_READERS` is reserved, like `_ORIGIN` and `_REVIEW`. An environment-defined domain whose name ends in `-readers` now stops the start. Rename the domain.
- On a server with a GitHub App, connecting a team domain needs an answer to who may read it: `--readers shared|private` off a terminal, `readers` in MCP `add_domain`.
