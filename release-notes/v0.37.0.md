# Choose Wisely

Pick the tools a domain installs on your machine, ask for a fresh look at a Reflection page, keep new domains out of macOS's protected folders and get a working Discard back on open proposals.

## New & Noteworthy

**Pick the tools a domain installs.** A domain that ships skills, commands, agents or MCP servers was all or nothing on your machine: allow it and you got every tool, deny it and you got none. Now you can pick. `crystalline provision skip <domain> <kind/name>` leaves one out. On a domain you have not allowed, `crystalline provision take <domain> <kind/name>` takes only what you name; on an allowed domain it adds an optional tool. Names look like `skills/deploy-prod`, `commands/release` or `mcps/lighthouse`, exactly as `crystalline provision status` lists them (and case matters). The choice also says what happens when the domain ships a new tool later: on a domain you allowed (with or without skips) it is installed, on a domain where you only took some it is not. A skip on a domain you never decided on installs everything else. `allow` and `deny` still switch the whole domain, and `allow` keeps the optional tools you took. Your agent knows the same two actions in the `provision` tool, and for a new domain it asks you "all, none or pick?". The choice is per machine. Fluid's Provisioning card shows the list of tools, but it does not decide for you.

**Optional tools.** A domain's author can mark a tool as optional: `metadata: { provision: optional }` in a skill's or command's frontmatter or in an MCP config. An optional tool is installed only when you take it. A team can ship its risky deploy skill without putting it on every laptop. An agent written as `.toml` cannot carry the mark (Codex refuses the extra table), so write it in Markdown if it should be optional.

**Mark a page as not fresh.** You import new engrams, and the Reflection page that shows them waits for its next scheduled run. Now you tell it to look again. "Mark as not fresh" in a page's More actions menu marks the page and the pages it owns. The page shows "Not fresh: marked by Jordi at 10:42" until a run has reconciled it. The run takes a real look: it reads the pact and the presentation rules again and searches the sources, also when no source changed. A marked page is due at once, so the webhook goes out without the 30 minute quiet time. A pipeline marks pages right after it wrote its engrams: `POST /api/v1/domains/{domain}/reflection/mark-stale` with `path`, `pages` or `all: true`, or `crystalline reflect mark-stale <domain> [<page>...]`. Anyone who may edit the page may mark it. An unattended run may not. The reconcile that saw the mark takes it off the page again.

**New domains go to `~/.crystalline`.** On a Mac, a process that a harness or launchd starts often may not read `~/Documents`, and every domain there answered "Operation not permitted". So a new domain without a folder now goes to the hidden folder `~/.crystalline` (on Windows `%USERPROFILE%\.crystalline`). Crystalline creates it with the first such domain: readable only by you on macOS and Linux, hidden on Windows. Your domains are not supposed to need your hands, but Cmd+Shift+. in Finder shows the folder if you want to look. `crystalline doctor` says where new domains go and why.

## Fixes

- Discard on a file that is already in an open proposal did the wrong thing. If the proposal added the file, Discard refused with "Its earlier content is in an open proposal below this one; withdraw that layer to get it back", so undoing one removed tag meant withdrawing the whole proposal. If the team already had the file, Discard silently put back the team's older copy and threw away the proposal's change on your machine, and the next share would have proposed that old copy. Now Discard goes back to what the change list compares your file with: the content of your open proposal. The diff shows that content as the earlier side too. Withdrawing an upper proposal had the same mistake and is fixed too. Crystalline keeps a copy of every file it shares in a proposal, so this works offline. When that copy is missing, for example for a proposal shared with an older version, it reads the file once from GitHub (it still never writes there). If the last share into that proposal did not finish, Discard asks you to share into it again first.

- Saving `config.yaml` turned a file that only you could read (0600) into one everyone on the machine could read (0644). Now a save keeps the file's mode.

## Breaking changes

None, but read this before you upgrade:

- Existing domains never move. If at least one of your domains lives in `~/Documents/Crystalline` and you never set `domains_root`, Crystalline writes `domains_root: ~/Documents/Crystalline` into your `config.yaml` once, so new domains keep landing beside the old ones. This rewrite drops comments and keys it does not know. A `config.yaml` that is a symlink stays a symlink: Crystalline writes through it. If your domains all live somewhere else, new ones now go to `~/.crystalline`. To use the new place anyway: `crystalline config set domains_root ~/.crystalline`.
- A backup that covers only `~/Documents` (or iCloud "Desktop & Documents") does not include `~/.crystalline`.
- A pick (`skip` or `take`) is stored as a list, and older Crystalline versions cannot read that `config.yaml`: a downgrade, an old daemon still running, the Claude Desktop-only bundle or an older server reading a shared config. Crystalline warns you when you make such a pick. `deny`, or `allow` when you took no optional tool, writes a value every version reads.
- When an author marks a tool you already have as optional, it is removed on the next update unless you take it. You get one notice with the `take` command.
- A tool whose frontmatter Crystalline cannot read counts as optional until it is fixed, so it is removed on the next update. You get a notice that names the file.
- A misspelled `provision` entry in `config.yaml` (for example `exept`) now stops the config from loading, with a sentence that names it. `crystalline doctor` reports it as a problem.
- Discard may now read from GitHub when it has no local copy of a proposal's file.
- Skipping a tool removes it from your harness the way a denied domain's tools go: a file you edited is kept as `.bak`, a file that matches the domain's copy byte for byte is removed.
- `crystalline provision status --json` has new fields per domain (`selection`, `artifacts`, `stale` and `malformed`), and `decision` can be `only`.
- Update the CLI together with the daemon: a 0.36 CLI that adds a domain on its own still puts it under `~/Documents/Crystalline`.
- The reflect prompt changed with this release, so its checksum changed too.
