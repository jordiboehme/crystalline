# A glitch in the Matrix

Many small gaps, closed: on Windows, in containers, in Fluid and in a few places you would rather not find them.

## New & Noteworthy

**Secrets from files.** A container keeps its secrets in files, not in the environment. `CRYSTALLINE_AUTH_OIDC_CLIENT_SECRET_FILE`, `CRYSTALLINE_GITHUB_TOKEN_FILE` and `CRYSTALLINE_REMOTE_TOKEN_FILE` read the secret from a file, like the admin variables already did. Set both forms and Crystalline does not start and names both.

- `CRYSTALLINE_SETUP_TOKEN` (or `CRYSTALLINE_SETUP_TOKEN_FILE`) sets the setup token yourself. It needs at least 32 characters and is never printed.
- `crystalline users add --password-file <path>` sits next to `--password-stdin`.

**Network, database and sign-in belong to the operator.** An agent with admin rights could change `auth.mcp` or `database.url` through `configure`. Now these settings live in the CLI only: `configure` does not list them and refuses to change them. `crystalline config set` works as before.

**Create a MANIFEST in Fluid.** A domain without a MANIFEST.md offered "Edit MANIFEST" and then showed an error. Now the editor opens with a starter, and Save creates the file.

**Windows: the task knows who you are.** The per-user task now carries your account's SID in its name, so a local `bob` and a domain `bob` no longer share one. `crystalline doctor --fix` moves your old task.

- A daemon the sign-in task started does not see the variables of your shell. `crystalline status` and `crystalline doctor` now say so and name the variable.
- An MSI update ends the running Crystalline daemons before it replaces the files.

## Fixes

- Delete an engram, and links to it from other domains still showed as resolved. Removing a domain did the same. These links read as pending now, and a restore binds them again.
- `validate_engrams` and the check in Fluid's editor ignored the rule overrides in a domain's `.crystalline.yaml`. `crystalline verify` used them. Now all of them do.
- One value that is not a word in `.crystalline.yaml` (for example `E007: 1`) dropped every override, with a hint about YAML syntax. Now only that rule is reported, and the others still apply.
- A refused `domain add` left an empty folder behind.
- `domain add --json --private` on an adopted domain printed success and then exited with an error. It prints an error object now.
- Mermaid labels were cut off in Safari with page zoom.
- `crystalline doctor --fix --merge-desktop-state` dropped the `github` settings of the old state. It now carries the ones your config does not set.
- On Windows a task query that Windows refused counted as "no task", so an uninstall could leave a task behind without a word. It says so now.
- A disabled delete button could still open its confirm panel. The confirm did nothing, but the panel should not open.
- The branch of a withdrawn proposal could stay on GitHub when the withdraw finished on a later try.
- Removing a model from the cache left its download lock folder behind. `crystalline doctor --fix` cleans up the old ones.
- Texts say "1 file" and "3 files" instead of "file(s)".

## Breaking changes

- `configure` no longer lists or changes the network, database and sign-in settings: every `auth`, `database` and `service` key except `service.response_format`, plus `github.api_url` and `github.oauth_client_id`. Use `crystalline config set`, `config.yaml` or the environment variables.
- The Windows per-user task has a new name, `\Crystalline Daemon for <name> (<SID>)`. Run `crystalline doctor --fix` once to move the old one.
- Output that said "file(s)" now says "1 file" or "3 files". A script that matched the old text needs an update.
