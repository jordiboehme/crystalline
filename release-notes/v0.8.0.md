## New & Noteworthy

- **Domains ship working tools, not just knowledge.** A domain's MANIFEST can declare a `## Provisioning` section naming folders of skills, slash commands, agent definitions and MCP server configs. Crystalline installs them into your coding harnesses after a one-time per-domain allow or deny, keeps them current when the sources change, retires what a domain stops shipping and preserves your hand edits as `.bak` copies. Drive it with `crystalline provision`, the gated `provision` MCP tool for mid-session decisions or just let session start keep things fresh; `crystalline doctor` reports installed state, drift, edits and pending decisions.
- **Authored once, translated per harness.** Artifacts stay byte-identical for their native harness and translate across dialects where the formats allow: nested Claude commands flatten to Codex prompts and back, markdown agents and Codex TOML agents convert in both directions and MCP servers register on Codex and Copilot too.
- **Team domains ship tools as well.** A GitHub team domain's out-of-subtree artifact folders (such as `../skills`) arrive through the same trusted pull channel as the knowledge itself, always at the fetched commit, with hostile paths refused before anything touches disk.
- **Two new platforms.** macOS Intel and Windows ARM join every release: standalone binaries, an arm64 MSI, Homebrew now serves Intel Macs and Claude Desktop bundles exist for both.
- **Knowledge retires without disappearing.** The capture and memory skills teach reconcile-in-place hygiene: supersession closes validity windows, retired experience can distill into durable lessons and outdated engrams may deliberately stay on record as anti-pattern warnings.

## Fixes

- Connecting to GitHub states the enablement status explicitly in every connect response, so an agent can no longer misread an enabled instance as disabled regardless of the order of configure and connect.
- Provisioning counts report skills as skills rather than as their individual files.
- Env-defined team domains no longer surface in the session pending block asking for a decision that lives in the environment.

## Breaking changes

- The env-defined domain setup flow is renamed from provision to bootstrap: the origin-update payload's internal `provisioned` key is now `bootstrapped` and the log lines follow suit. The provision verb now exclusively means artifact provisioning.
- The release workflow's Windows MSI artifact is named `crystalline-msi-windows-amd64` (previously `crystalline-msi-amd64`); only CI-internal consumers are affected.
