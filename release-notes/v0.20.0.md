# Say my name

A domain now carries its own name, so links between domains survive every machine they travel to.

## New & Noteworthy

- A domain can say what it is called. Put `domain_name: eng` in its MANIFEST and every machine knows it as `eng`, whatever the folder or repository is called. You can still pick another name on your machine: links written with the declared name reach it anyway, and links you write are stored with the declared name. So a link that works for you also works for your colleagues.
- Rename a domain everywhere with `crystalline domain rename <domain> <new>`, the REST API or the Rename button on the domain page in Fluid. Crystalline writes the new name into the MANIFEST and rewrites the links in every domain you can write. Links in domains you can only read stay as they are, and the rename tells you where they are. Old names keep working, and old web addresses send you to the new place.
- Add `--local` (or tick "This machine only") to change only your machine's name. The MANIFEST and the links stay as they are.
- A rename is safe when things go wrong. If Crystalline stops halfway, it finishes the rename on the next start. If it cannot, `crystalline doctor` shows the rename that is left and the command that finishes it. `crystalline doctor --discard-rename` drops it when you really want that.
- When you connect a GitHub repository, the name is now optional. Crystalline takes the MANIFEST's `domain_name`, then the repository name. Fluid shows the name it will use before you connect.
- When the MANIFEST name changes upstream, your machine follows after the next sync. It does not follow if you picked a name yourself.
- `crystalline doctor` explains name problems: two domains that want the same name, a declared name that another domain already holds here, and links that use a name only your machine knows (`--fix` rewrites them). For a team domain without `domain_name`, it asks you to have the owner add one.
- Evolve finds links that use a name only your machine knows, and it tells the agent the exact edit to fix them.
- `crystalline verify` reports a `domain_name` that cannot be a domain name (M008). Until you fix it, Crystalline ignores the value and the domain keeps its name.
- `list_domains` and the REST domain list show each domain's declared name, its former names and whether another domain holds its name.
- Crystalline is now built from smaller parts, so a change rebuilds much faster. You can see this in the logs: lines now say which part they come from (`crystalline_engine`, `crystalline_rest`, `crystalline_identity` or `crystalline_service`). If your `RUST_LOG` filter names `crystalline_service`, it now only covers the daemon's own lines. Name the crate you want, or use a plain level like `debug`.

## Changed behaviour

- Crystalline no longer writes `domain_name` into a team domain's MANIFEST. The owner adds it in the repository, and doctor tells you when it is missing.
- `crystalline domain remove` now also clears the removed domain's leftover entry in the index, so the name is free again. `doctor --fix` clears entries that older versions left behind.
- A GitHub folder path with `..`, `%` or a backslash is refused before Crystalline asks GitHub.
- The index gets a small upgrade on the first start. It runs by itself; there is nothing to do.

## Breaking changes

None.
