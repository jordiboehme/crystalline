# Hello · Hallo · Hola · Bonjour · Ciao · Olá · Hoi · Ahoj · مرحبا · こんにちは · 안녕하세요 · 你好

Search reads your knowledge in whatever language you wrote it in, and every prompt starts with what an earlier session already learned.

## New & Noteworthy

**Search speaks your language.** People write down what they know in the language they think in. An English question found little of it. The built-in embedding model reads more than 200 languages, 52 of them with retrieval training, so a German engram answers an English question and the other way round, and a domain that mixes languages needs no translation and no second index. Close enough to a universal translator for daily work. The model is new in this release, so the first start after the upgrade has some work to do: see the note at the end.

**Every prompt arrives already taught.** An agent only searches when it thinks of searching, and it often does not. `crystalline install` now wires a hook that puts the engrams a prompt may need in front of the agent before it answers, each named by its address, at most three per prompt and each one only once per session. It costs about 200 tokens when it has something to say and nothing when it does not. Claude Code and Codex have it today. Copilot gets the same hook entry, but there is no channel yet for what it would say, so it stays quiet there. Three settings steer it: `recall.enabled`, `recall.limit` and `recall.min_score`.

**The README is a pitch again.** You can read it in one sitting: it went from more than 600 lines to under 180, with what Crystalline is, two commands to start and one prompt that creates your first two domains. The manual moved to `docs/`: fifteen pages, one per topic, an index that lists them all and a diagram on the pages where a flow is easier to see than to read. Nothing was dropped on the way, it is only easier to find and easier to keep current. The pages ship with the product, so every release archive carries the `docs/` folder and the `.deb` installs it under `/usr/share/doc/crystalline/docs/`, next to the binary. The playbook is gone. The Handbook is the long read now: https://jordiboehme.github.io/crystalline/

**See what changed, and discard what you do not want.** Until now you shared everything that had changed and read it afterwards, on GitHub. Now both sides of every unshared file are one press away, and nothing about looking or discarding contacts GitHub.

- In the share dialog a path opens a diff of the team's copy against yours, side by side on a wide screen. A row's menu or the "Discard selected" button puts files back the way the team has them, after one confirmation.
- An engram page that differs from the team's copy wears an "Added" or "Changed" chip beside the title, or "Draft" in a domain that reviews changes. Its menu shows the change, shares only this file or discards it.
- `crystalline origin diff <domain>` prints a unified diff per unshared file. `crystalline origin discard <domain> --path <p>` previews, asks and restores.
- Agents get the same two things: `origin_status` with `diff: true` returns both sides of every unshared file, and the new `discard_changes` tool puts chosen files back, asking you first on a harness that can ask.

**Share straight to the branch.** A review step makes sense on a repository several teams read. On a domain three people keep for themselves it is one step too many. Set `sharing: direct` in the MANIFEST and every share commits the chosen files straight onto the branch, in one commit under the identity the domain shares with. A domain that says nothing keeps opening proposals, exactly as before.

- A direct share refuses while a proposal is still open and tells you to merge or withdraw it first. A branch whose rules do not allow direct commits answers with the way out. The agent's confirmation question says the change goes to the branch with no review.
- The domain page has a "Domain policies" card. Everyone sees every MANIFEST switch there, `generated_indexes` and `sharing` today, and the owner changes them without opening the editor. Turning direct sharing on asks once.
- `crystalline origin status` shows `sharing: direct` where it applies, `crystalline verify` reports an unknown `sharing` value as `M007` and `crystalline doctor` names it too.

**A browser link for every engram.** An agent that found something useful can hand you the page instead of the path. Every engram a tool reads or writes comes back with `web_url`, its page in the web UI, and a URL may end in a heading's slug to open the page at that section, scrolled to and briefly highlighted. Every heading in the web UI has a link symbol that copies the same URL. Where the daemon cannot work out the address people reach it at, behind a proxy, in a container or with a separate Fluid deployment in front, `service.public_url` names it. Unset, the address is derived per caller and a wildcard bind is never handed out.

**Fewer moving parts in the build.** The embedding model downloader runs over the same HTTP and TLS stack as everything else Crystalline fetches. It moved to hf-hub 1.0, which takes a whole second HTTP and TLS stack out of the workspace: the build is smaller and there is less to keep current. The Fluid test runner moved to vitest 5 and Node is pinned in the browser jobs.

**The dependencies carry their security fixes.** They moved up wherever a fix exists, including rustls 0.23.45, which carries the fix for RUSTSEC-2026-0285, and patched versions of three npm packages in the web UI's lockfile. Four advisories have no released fix yet and are tracked until one lands.

There is nothing else to report here: the rest of 0.19.0 is new work.

## Breaking changes

None. Two changes in behaviour are worth knowing about, though.

**The first start after the upgrade is a busy one.** The default embedding model changes, so the daemon downloads about 220 MB of weights and embeds your knowledge again. Search keeps working while that runs, falling back to plain text matching until the new vectors are in place, so results are rougher for a while rather than absent. On a large corpus that takes a while. The old model's weights are removed once the new one has loaded. To stay on the previous English-only model, set `embeddings.model: bge-small-en-v1.5`.

**Model download progress moves in steps.** For a large weights file the progress line now shows a few byte figures instead of counting up smoothly, because the new transfer reports a large file's bytes only when a chunk lands. Smaller files still count up.
