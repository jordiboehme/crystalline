# Who goes there?

## New and Noteworthy

- **Configurable HTTP `Host` allow-list.** The streamable HTTP transport can now serve clients that reach it by something other than loopback - a gateway, a reverse proxy, a LAN hostname or a container service-name like `http://crystalline:7411`. Set it with the repeatable `serve --allowed-host <host>` flag, the `CRYSTALLINE_SERVICE_ALLOWED_HOSTS` environment variable (comma-separated) or the `service.allowed_hosts` config key. It stays secure by default: with nothing configured the guard is loopback-only, configured hosts are merged on top of loopback so local access never breaks and a single `*` disables the guard for deployments that validate `Host` at a trusted reverse proxy or firewall.

## Fixes

- **HTTP clients behind a hostname or proxy.** The HTTP MCP endpoint returned `403 Forbidden` to every request whose `Host` header was not `localhost`, `127.0.0.1` or `::1` (rmcp's DNS-rebinding guard), which broke team-server, reverse-proxy and cross-container `http://crystalline:7411` access with no way to configure it. Those clients work again once their host is on the allow-list above; `GET /health` was and stays unguarded.

## Breaking changes

- None. With no allow-list configured the endpoint keeps its secure loopback-only default, so existing `localhost` access is unchanged.
