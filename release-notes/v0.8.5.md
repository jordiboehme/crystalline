## New & Noteworthy

**Temporal fields are now enforced, not just documented.** `valid_from`, `valid_to` and the other date fields must be plain ISO dates (YYYY-MM-DD). A timestamp where a date belongs fails the write with an error that says exactly what to fix; a sentinel far-future date or an explicit null is dropped, because absence already means valid forever. Valid dates land in the typed frontmatter and the search index immediately. Agents that guessed wrong used to get silence; now they get taught.

**`validate_engrams` runs the temporal checks.** Malformed dates, inverted validity windows and sentinel dates show up in the tool result, so a self-checking agent no longer needs the offline verifier to find out.

**Building from source got dramatically faster.** Dev builds carry line tables only and the test suites run through cargo-nextest: a full workspace test run finishes in about a minute and the target directory shrinks by two orders of magnitude. Release binaries are unchanged.

## Fixes

- Setting a temporal bound through `metadata` with the wrong format used to succeed while the bound silently never took effect, leaving the engram unbounded in search. It now either lands or errors - no more silent nothing.
- An edit can no longer blank `recorded_at`: nulling a required field is rejected instead of quietly producing an engram that fails verify.

## Breaking changes

- Writes and edits that previously succeeded with malformed date fields now fail with an error. That is the feature.
- `verify` T003 messages changed wording: string values are quoted and composite values render as "a non-scalar value". Update anything that parses verify output textually.


*Note added 2026-07-20:* this release also changed the wording of validate's T003 temporal check messages - offending values are now quoted and a non-scalar value is called out as "a non-scalar value". Omitted from the original notes by mistake.
