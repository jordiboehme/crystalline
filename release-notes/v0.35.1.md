# I Can See Clearly Now.

Reflection pages say what they follow, their settings read before they edit, the admin page tells you whether the update check runs, a thread resolves without a comment and the agent writes its pages for people.

## New & Noteworthy

**Reflection pages written for people.** A Reflection is read by people, but the agent wrote its pages in a careful, plain style: mostly prose, few tables, almost no colour. Now it shows the shape of what it writes. Something with a state gets a status label, and the colour means the same on every page: green for done, blue for in progress, yellow for at risk, red for blocked, purple for proposed and grey for not started. Attributes and options go into a table. Steps between parties, branches and states become diagrams, and dates become a timeline. A risky step gets a warning box right at that step. Knowledge that is not decided yet shows as "Proposed" instead of hiding in soft words. The text follows clear rules too: short sentences, plain words, every term explained the first time and no links a reader cannot open. Your `PACT.md` still has the last word: its `## Presentation` section wins over these defaults. A reflect run reads these rules even when the presentation skill is not installed in the agent (it fetches it from the server). Engrams stay as they are: they are the agent's own knowledge, in the form that works best for the agent. The reflect prompt changed with this release, so its checksum changed too.

**Page settings you can read.** The settings beside a Reflection page were always an open form, with Retire and Delete right under it. Now they are a short read-only list: Freshness, Follows, Status and Page pact. A curator presses Edit to change them, then Save or Cancel (Escape cancels too). Retire moved into the page's More actions menu, next to Move and Delete. Restore stays on the banner of a retired page.

**The update check says what it does.** Administration > General said "No newer release is known" whether the server checked this morning or never checked at all. Now the Updates section says it plainly. Check on: when it last checked and what it found. Check off: the command to turn it on on the server, with a copy button. Turned off by the install (Docker, the Claude Desktop-only bundle, `NO_UPDATE_NOTIFIER` or `CI`): why, and what to do instead. There is no switch on purpose: whether the server talks to GitHub every day is the operator's decision, so `update.check` is still set only with the CLI, `config.yaml` or `CRYSTALLINE_UPDATE_CHECK`. Only admins see this.

**Resolve a thread without a comment.** Closing a thread on a Reflection page needed an outcome text, even when there was nothing more to say. The outcome is optional now. Leave the field empty and press Resolve, and the thread shows "Resolved". Agents still write a short outcome where there is one.

## Fixes

- A Reflection page with its own page pact still said "Follows: PACT.md" under its title, as if the page pact was not there. The agent did follow it. The line is called "Pacts:" now and lists every pact file that applies, the page's own pact last. A pact file that does not exist is not listed.
- The settings beside a page showed "Follows: Not set" while the line under the title said "Follows: PACT.md". Both were right, but they meant different things. The setting now reads "No page, only PACT.md".

## Breaking changes

None. Two changes in behaviour: Retire is in the More actions menu of a Reflection page now, not in the settings column. And reflect runs write richer pages than before: more tables, status labels and diagrams. A domain that wants the old plain style says so in its `PACT.md` under `## Presentation`.
