# I feel the need, the need for speed

A patch for faster embedding on Apple Silicon Macs, a Help menu in the web UI and a round of dependency updates.

## New & Noteworthy

**The embedding model runs on the GPU of Apple Silicon Macs.** Embedding a big domain used to keep every CPU core busy for minutes. On a Mac with Apple Silicon the model now runs on the GPU through Metal: on an M5 it embeds almost twice as fast (11 chunks per second instead of 6) and leaves the CPU nearly free for everything else. The results are the same (the vectors differ in the seventh decimal place), so nothing is embedded again after the upgrade.

- `crystalline status` shows where the model runs: `device: metal`, or `device: cpu` with the reason.
- If Metal is not available (a virtual machine, for example), Crystalline uses the CPU as before and says why.
- `CRYSTALLINE_ACCELERATION=off` forces the CPU.
- The first start after the upgrade takes about 15 seconds longer, once: macOS prepares the GPU programs.
- While it embeds, the model uses more memory on the GPU than on the CPU (about 0.7 GB more at the peak). After it is done, it uses less.
- Intel Macs, Linux and Windows are unchanged. Intel Mac GPUs lack features the GPU code needs.

**A Help menu in the web UI.** The question mark next to your account opens the Handbook in a new tab and the keyboard shortcuts. The shortcuts were only reachable with `?` before, which you had to know about. The command palette has "Open the Handbook" too.

**Updates.** Rust 1.98.1 (it fixes a compiler bug that could produce wrong code), the MCP library rmcp 3.5.0, the embedded database turso 0.8.1 and the usual patch updates. Nothing changes in how you use Crystalline.

## Fixes

**The web UI's top bar didn't fit on a phone.** On a narrow screen the bar was wider than the screen, so the account menu was cut off. Below tablet width the bar is compact now: the width toggle is hidden (the content is always full width on a phone), Share and Maintenance show only their icons and your account shows as an icon. From 768 pixels up it looks as before.

**The daemon's memory grew a little with every write.** The embedded database kept a small piece of memory for every commit, for as long as the daemon ran. turso 0.8.1 fixes this. It is also safer after a crash or a power loss.

**A network error could get lost.** A read error on a TLS connection could be dropped, so a GitHub sync or a model download didn't always see it. tokio-rustls 0.26.6 passes it on.

**A security advisory in the web UI.** DOMPurify, which cleans the HTML of diagrams, is at 3.4.16 now (GHSA-p98j-92pf-mc4p, low).

## Breaking changes

None. The index opens with 0.21.2 and 0.21.3 alike, so you can go back if you need to.
