# I don't even see the code anymore.

Tables you edit as tables, agents that handle files like people do, and links that land on a heading.

## New & Noteworthy

**Tables are a grid now.** A Markdown table is a fine format to store and a poor one to type in: one missed pipe and the row is gone. In Fluid you now edit a table as a grid and never see a pipe or a dash.

- Click a cell and type. Tab and Shift+Tab move between cells, and Tab in the last cell adds a row. The arrows, Enter and Escape work as in a spreadsheet.
- Add, delete and move rows and columns from the cell actions menu (right-click, Shift+F10 or the small button on the open cell) or from the "+" on a border. Alignment too.
- Paste from a spreadsheet fills the cells. Search and replace work inside cells. You see your collaborators' carets in the cells they are in.
- Only the bytes you change are written. Everything else in the file stays as it was, so a diff on GitHub shows your edit and nothing more.
- Tables without outer pipes (`a | b`) get the same grid. New rows keep the table's spelling.
- Raw mode shows the source as before.

**A format bar where you are.** Select text, or open a cell, and a small Quick format bar shows up next to it: bold, italic, code, links and, in a cell, the table actions. Alt+F10 reaches it from the keyboard. Escape hides it until you move the selection.

**Agents and people in one table.** People typing in the same table already merged per character. Now an agent's edit does too.

- When an agent changes one cell while you type in another cell of the same row, both changes land, and your cell stays open. Before, this stopped the save and showed you a conflict.
- When it is not certain which change belongs where, you still get the conflict. A wrong merge would lose your text without telling you, and a conflict only asks.

**Agents handle files.** An agent could read a picture, but it could not change one. On a remote or shared domain that meant a person had to copy every file by hand. Now an agent downloads and uploads engram attachments and Reflection files itself, with the same access rules, limits and history as a person.

- `read_engram` and `write_engram` take a path under `assets/`. `read_reflection` downloads a Reflection file, and `write_reflection` has a new action `write_asset`.
- Text files come back as text, binary files as base64. A picture comes back as an image the agent can look at; with `include_images: false` it comes back as base64, so the agent can copy it byte for byte.
- An open page in Fluid redraws a changed picture without a reload.
- It works through a connected server too.
- The scheduled reflect run copies an engram attachment into `reflections/assets/` itself, where it used to ask a person.

**Links to a heading.** `[[page#Setup]]` now links to the page and opens it at the heading Setup. Fluid shows it as "Page › Setup". Moves and renames keep the heading as you wrote it. A title that holds a `#`, like `C# Basics`, is still read as a whole first, so those links keep working.

**Archived repositories are read-only.** GitHub refuses pushes to an archived repository, and Crystalline now says so before you type. When the repository of a team domain is archived, the domain becomes read-only for everybody, instance admins and the machine owner included. Reading, search and pulls keep working. Every write is refused with one sentence that names the repository, and the Members card shows it. When the repository is unarchived, the domain can change again.

**Organizations that move or go.** A domain follows a renamed GitHub organization, but only after GitHub's own API confirms the repository and owner ids, so a replayed webhook can't move it anywhere. A deleted organization closes its domains.

## Fixes

- An agent's change to one cell of a table, while somebody had another cell of the same row open, stopped the save and showed a conflict. Both changes now land.
- `crystalline verify` warned about a `crystalline://` link with a `#heading` as if it were broken. It checks the engram now and leaves the heading alone.
- `[[b#setup]]` never resolved, and a move named it in `links_dead`. It resolves now.

## Changes

- After the update, every domain is read again once, so heading links resolve. The index gets one new column (migration 30, for the embedded database and Postgres).
- A link with a heading carries `fragment` in `read_engram` and in the REST engram detail. A link whose text can't be rebuilt from its target and heading (like `[[C# Basics]]`) also carries `whole`.
- A link to a heading in the same engram is no longer reported as a self-link.
- MCP over HTTP and the remote control protocol accept bodies up to 15 MiB, so a full-size file fits as base64. The bundled nginx template allows it. If you run your own proxy in front of Crystalline, raise its body limit to 15 MiB for the MCP endpoint and `/api/v1/ctl` (see docs/deployment.md).
- On a domain whose repository is archived, the owner can't switch the MANIFEST `read_only` off. Taking GitHub's side of a sync conflict still works. Scheduled runs leave such a domain out and name it.

## Breaking changes

None.
