# Avengers Assemble!

Reflection pages can now bring together the knowledge of several shared domains, and the reflect run can read it.

## New & Noteworthy

**Pages that draw on other domains.** A Reflection page often needs knowledge that lives in other domains. A product page shows the architecture, the teams that build each part and the people in each team, and every team keeps its own domain. Until now the source rule refused most of this: a single account that reads only the Reflection was enough to stop a shared page from citing any other shared domain. A page backed up to GitHub could not cite a local domain at all, and the reflect run could not even read those domains. Now a page of a shared domain may cite every other shared domain on the server. A page of a private domain may cite shared domains too. Private knowledge stays protected: a page cites a private domain only when everyone who reads the page may also read that domain's engrams. The reflect run reads what its pages may cite, so it can now build such pages on its own.

**Two settings decide how open this is.** Both are open by default, and you can make them stricter:

- `reflection.cite_shared`: `on` (default) lets shared domains cite each other as described above. `off` brings back the old rule, where every reader of the page must read the source's engrams.
- `reflection.backup_sources`: what happens when a page backed up to GitHub cites a domain the repository's readers may not read.
  - `full` (default): the page is written and backed up in full. The text then reaches everyone who can read the repository. For a public repository that is everyone. A thread answer or an engram a run writes can carry such text to the repository too.
  - `hold_back`: the page is written and served here, but stays off the GitHub backup. A reflect run then reads like under `refuse`, so its threads and engrams carry nothing to the repository.
  - `refuse`: the old behaviour. The write is refused.

Both are operator settings: you set them with `crystalline config set`, in `config.yaml` or with `CRYSTALLINE_REFLECTION_CITE_SHARED` and `CRYSTALLINE_REFLECTION_BACKUP_SOURCES`. No agent and no other surface can change them. A change takes effect at once, without a restart. Moving away from `full` takes the pages off the head of the backup branch, but the branch history keeps them.

## Fixes

- A person who shared a source on purpose under `hold_back` was asked only about the accounts here, never about the GitHub repository. After a switch to `refuse` this yes counted for the repository too. It does not any more.
- A session marked unattended but without a lease could change instance settings and so widen what it may read. Every session with a read limit is now refused such a change.

## Breaking changes

None, but read this before you upgrade a server whose domains are backed up to GitHub. With the new default `reflection.backup_sources: full`, the first backup after the upgrade sends pages that 0.35 held back only because of the GitHub rule, for example a page that cites a local domain. The server logs a warning for every page it sends this way. To keep the old behaviour, set `reflection.backup_sources: refuse` (or `hold_back`) before you start 0.36.0. The reflect and evolve prompts changed with this release, so their checksums changed too.
