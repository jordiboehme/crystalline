# Trust, but verify

A release for the people who have to approve Crystalline before anybody may install it. Every release file now says where it came from.

## New & Noteworthy

**Check where a release came from.** Every file of a release now has a build provenance attestation, the checksum file included. It proves that the file was built by this repository's release workflow from the tagged source. Check it with the GitHub CLI:

```
gh attestation verify crystalline-v0.21.2-windows-amd64.msi --repo jordiboehme/crystalline
```

**Know what is inside.** Each release now ships CycloneDX SBOMs: one per platform for the binary and one for the web UI. They list the dependencies that ship, with their versions and, where a package declares one, its license. They are attested too.

**Dependencies are checked on every change.** CI now runs `cargo-deny` (known vulnerabilities, licenses and sources) and `pnpm audit`. A new license needs a deliberate change to an allowlist. Release builds use `--locked`, and the build tools are pinned to exact versions.

**The embedding model has a fixed version.** Crystalline downloads the model at a pinned commit instead of whatever is newest. If your cache already holds that version, nothing is downloaded.

**Security, written down.** `SECURITY.md` says how to report a vulnerability privately. `docs/security.md` explains what Crystalline can access next to your agent harness, every connection it can make and how to turn each one off, what it writes where, and which gaps are still open. The privacy section in the README now lists every outbound connection.

## Breaking changes

None. An install whose model is at an older version keeps working and moves to the pinned version by itself at a later start, once it could download it. `crystalline doctor` shows which version is in use.
