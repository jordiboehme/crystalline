# Say what you mean

Eight places where the docs, the help or the UI promised something the code
did not do: a routing rule, a branch, a second `domain add`, a name check, a
button, a refusal, a config typo and some texts.

## New & Noteworthy

**`RUST_LOG` works.**

Two comments promised it and nothing read it. Now the daemon, `crystalline
mcp` and every other command take a `RUST_LOG` filter, for example
`RUST_LOG=debug` or `RUST_LOG=crystalline_service=debug,warn`.

Default for `serve`: `info`. Default for everything else: `warn`.

Logs go to stderr only, so the routing block, hook output and the MCP stream
stay clean. A hook logs only when you set `RUST_LOG`.

## Fixes

**A `prompt.rules` pattern ending in `/**` matches the folder itself.**
`~/work/website/**` matched `~/work/website/src` but not `~/work/website`. So a
session started in the repository root (the usual place) got no rule and
heard about every domain. Now the folder counts too.

Also, `crystalline prompt system` without `--workspace` (or with
`--workspace .`) matched a relative path against absolute patterns, so only a
bare `**` ever applied. The workspace is made absolute first now.

**A team domain added without a branch tracks the repository's default
branch.** Fluid and the API docs said so, but the engine used `main`. A
repository whose default is `trunk` or `master` got a domain that tracked the
wrong branch, or one that doesn't exist. Now Crystalline asks GitHub and
writes the answer into the domain's entry. If GitHub can't answer, the add is
refused and asks you for `--branch`.

Domains added before keep tracking `main`. `CRYSTALLINE_DOMAIN_<NAME>_ORIGIN`
without `@branch` still means `main`: it is read at startup, with no call to
GitHub.

**A second `domain add` no longer replaces a domain.** `crystalline domain
add <name>` on a registered name replaced the entry and said nothing. A team
domain lost its origin, its provisioning decision and review mode.

Now the same name at the same folder is kept as it is and indexed again, so
the command is safe to repeat. The same name at another folder, or as the
other kind of domain, is refused with a message that names the existing
registration. And connecting a GitHub origin to an existing domain no longer
drops its provisioning decision and review mode.

**Every surface checks domain names.** Only Fluid did. From the command line
or through `add_domain` a name with a space, a slash or `CON` got registered,
and then broke in a `crystalline://` address or on a Windows checkout. Now the
CLI, `add_domain`, the API and `domain init --name` refuse the same names with
the same message. Names registered before keep working. A name made from a
folder or a repository always passes (a repository called `CON` becomes
`con-2`).

**The owner of a private domain can unregister it in Fluid.** The server
allowed it, but the Danger zone showed the button to admins only. Now the
owner gets the button and the palette row too.

**`configure` on a read-only instance says why it refuses.** The refusal is
on purpose. An agent there can't act on any setting, and a public instance
should not show its paths and sign-in setup to anonymous readers. The message
now says this and names `crystalline config show`. The deployment guide no
longer promises a bare `configure` on every instance.

**A typo in the verify settings is reported.** A severity word verify doesn't
know (`E007: of`), or a `.crystalline.yaml` that doesn't parse, changed
nothing and said nothing. Your override was just gone. Now each one is an
`M108` warning against `.crystalline.yaml`, in `crystalline verify` and in
`validate_engrams`. It never fails a run on its own. `--strict` makes it an
error like any other warning. And a typo no longer stops `--strict` from
promoting the rule it was meant for.

**Help and docs match the code again.** `crystalline config --help` describes
the whole settings registry. The deployment guide says an unknown
`CRYSTALLINE_GITHUB_SHARE_IDENTITY` stops the daemon at startup. The teams
guide shows a local agent as `you (agent: <client>)`.

## Breaking changes

None.

Behavior changes you may notice:

- `domain add` refuses a name that is registered at another folder. It used to
  replace the entry.
- A new domain name uses letters, digits, `-`, `_` and `.`, 64 characters at
  most.
- A team domain added without a branch has its branch written into its entry.
- `domain add --json` has a new `adopted` field.
- `domain add --private` refuses a domain that was already registered. Use
  `crystalline domain visibility` for that.
- CLI commands now print warnings on stderr that were silent before.
