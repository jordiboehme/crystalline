# v0.18.1

A patch release for one report that turned out to be three bugs wearing a trench coat. No new features; if you add domains from the CLI while the daemon runs, you want this one.

## Fixes

- A domain added with `crystalline domain add` while the daemon was running was missing from Fluid's home screen and from the `list_domains` tool until the daemon restarted, even though agents could read it, write to it and find its engrams in search. The listing now sees every registration, not only the ones the daemon started with (#70).
- Found on the way, and worse: the next daemon-side config write after such an add (`config set`, `add_domain` over MCP, `domain remove`, a review mode change) saved `config.yaml` from the daemon's stale copy and silently unregistered the domain you had just added. Every config write now loads the file from disk first. Nothing beyond the registration line was ever lost: `domain add` it again and it is back, files and index included.
- `crystalline domain remove` of such a domain answered "not registered" and named it among the registered domains in the same sentence. It removes it now.
- `domain add --virtual` from the CLI while the daemon was running showed up in the routing block with the "routing information unavailable" placeholder instead of its MANIFEST bullets.

## Breaking changes

None.
