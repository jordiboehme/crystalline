# I don't even see the code anymore: Reloaded.

The editor hides the marks, shows your pictures and lets you edit flowcharts and sequence diagrams on the drawing. Claude Desktop installs with one command.

## New & Noteworthy

**The editor hides the marks.** You type `**bold**` and see bold. The `**`, `_` and backticks stay out of sight, so the page looks like the page. The avatar menu has "Show Markdown marks on the line I edit" to show them again, and Raw mode is as it was.

- Bold, italic, strike, code and links work from the toolbar, the floating bar and the keyboard. Cmd+K (Ctrl+K off a Mac) in the editor makes a link and opens the Link popover. A format pressed with no selection applies to the next text you type.
- Deleting never breaks a pair of marks. If a delete would break one, it moves so the pair stays, or merges with its neighbour. If neither works, you read "This text cannot be joined here."
- Typing over a selection, paste, drop and Enter at the edge of a format keep the pairs. Enter at the end of a bold list item starts a new item outside the bold.
- Input on phone keyboards and in Japanese, Chinese and Korean is checked when the composition ends. One undo goes back to before it.
- Task boxes, callout heads, status labels, math, link popovers, footnotes and linked images edit in place. Footnotes show as numbers, as on the reading page. An observation's `[category]` and a relation's type show as chips.
- A code block is a box with the language on top. A click on the language opens the Code language menu. A fence that is not closed yet stays as you wrote it.
- A table cell shows bold, italic and code while it is open.
- Copy from the editor carries formatted text too, so a paste into a mail or a document keeps headings, lists, links and tables. A paste back into Fluid gives the same Markdown, byte for byte.
- Formula source is never read as Markdown. An unclosed `$$` runs to the end of the page, as on the reading page.
- A large format command or delete on a big page gets more time to read it. If that runs out, it says "This page is still loading. Try again in a moment."

**Pictures where the Markdown has them.** The editor draws a picture and no longer shows `![...](...)`.

- Drop or paste a file. Drag a picture to move it to another place in the text.
- Select it with a click or the arrow keys. Delete it like a character.
- Resize it with the handles. A picture that floats left or right has handles only on the side it can grow.
- Edit the alt text in place.
- Float it left, right or center. In the editor the text does not wrap beside a floated picture, so lines do not jump while you type. The reading page is unchanged.
- Bold, italic, strike and code are off on a selected picture, and the button says why.

**Diagrams you edit on the drawing.** A diagram is a picture, so you should not have to edit it as text. Flowcharts and sequence diagrams are now edited on the drawing, in an engram and in a Reflection. Raw mode still shows the Mermaid text. Every change writes only the lines it means inside the fence, so a hand-written diagram keeps its comments, spacing and order. One undo takes a change back.

- Flowchart (`flowchart` and `graph`): click a box or an arrow to rename it in a field over the drawing. A box's menu has Rename, Add child, Add sibling, Connect to..., Shape, Colour and Delete. An arrow's menu has Edit label, Line, Arrowhead, Reverse and Delete. On the empty drawing: Add box, Direction and Delete diagram.
- Sequence (`sequenceDiagram`): click a participant or a message to rename it or edit its text. A participant's menu has Rename, Add participant, Add message to... and Delete. Add message to... asks for the participant the message goes to. A message's menu has Edit text, Move up, Move down, Line (Solid or Dotted), Arrowhead, Remove block and Delete. On the empty drawing: Add participant and Delete diagram.
- Move up and Move down take a message one step. A message passes a whole block and never goes into one. At the first or last place in a block it moves out of it. Alt+Up Arrow and Alt+Down Arrow (Option on a Mac) do the same from the keyboard, and the focus goes with the message.
- Deleting a message that opens or closes an activation also removes the matching mark on the other message.
- A diagram is one Tab stop. Inside, the arrow keys move through the boxes and then the arrows, in the order of the source. Home and End jump to the first and the last. Enter or F2 renames. Shift+F10 or the menu key opens the menu (Ctrl+Return on a Mac). Delete or Backspace deletes. Escape goes back to the text. When the diagram ends the page, Enter on the drawing opens a line below it.
- When a change cannot be written safely, nothing is written and a sentence says why. This also covers a colleague who changes the diagram at the same moment. A greyed menu item says why it is off.
- Other diagram types (state, timeline, gantt, ER, class and the rest), a diagram the editor cannot read and a mermaid fence that is not closed yet stay as before: the text, with the drawing below it.

**Download a diagram as a PNG.** A user asked for this. The full window of a diagram has Download PNG next to the source and SVG downloads. The picture is made in your browser, nothing goes to a server.

- The scale comes from the drawing's own size, at least 2x, so small text stays sharp.
- The background is solid, from the current theme, so dark text never sits on a transparent page.
- A diagram too large for the browser saves at the largest scale that fits and says so. If its text would come out too small to read, no file is saved and the sentence points to the SVG.
- A diagram with pictures inside cannot be saved as a PNG, and it says why.

**Every shortcut has a Mac key.** A Mac has no menu key, and F10, Home and End need fn on a MacBook. So every shortcut that uses them has a Mac key now.

- Menu of the item you are on (a diagram part, a table cell, a task box, a link): Shift+F10 or the menu key, Ctrl+Return on a Mac.
- In a diagram, Home and End: Cmd+Up Arrow and Cmd+Down Arrow on a Mac.
- In a table, Ctrl+Home and Ctrl+End go to the first and the last cell (Cmd+Home and Cmd+End on a Mac). On a Mac, Cmd+Up Arrow and Cmd+Down Arrow go to the first and the last row of the column.
- The help (`?`) names each key the way your keyboard does, for example ⌘K on a Mac and Ctrl+K elsewhere. It now also lists the menu key and Alt+F10 for the toolbar.

**Tabs and PDFs carry the page's name.** Every tab was called "Fluid", and Save as PDF suggested "Fluid.pdf". Now a tab reads `Engram title - Fluid`, for engrams, Reflections, domain pages and the other screens. Save as PDF suggests `Engram title.pdf`, also with Cmd+P.

**The QR stamp is a link.** The QR stamp on a printed page is now also a link to the page. A PDF made from the print keeps it, so a reader can click the stamp instead of scanning it.

**Comment from a bar at the selected text.** On a Reflection page you had to select text, scroll up to the threads and press Comment there. Now a small bar with Comment stands next to the selection. It shows for everybody who may comment, and it never covers the threads. A press opens the form on that passage. On a small screen the threads sheet opens with it. Alt+F10 moves to the bar and Escape goes back to the page with the selection kept.

**Shares carry the person's name.** With a GitHub App, the App opened every proposal, also for a person who had linked their own GitHub account. Now, with an App and `github.share_identity` not set, each proposal goes out as the person who shares. Branch protection that asks for another person's approval works as it should.

- The profile card and the share dialog say what really happens. An editor with no link is told to link.
- A scheduled reflect or evolve run on the machine itself shares through the App, as the machine's own work.
- A set `github.share_identity` still wins.

**Claude Desktop installs with one command.** `crystalline install claude-desktop` builds the extension on your machine and opens it in Claude Desktop, where you confirm the install dialog. You do not download anything for each release any more.

- The extension runs the crystalline you have installed, also one installed with cargo. It names the crystalline found first on your PATH. If that path is gone or too old, it searches as before. So the path can never stop a working crystalline from starting.
- After an upgrade, the first start from Claude Desktop builds the extension again and opens it, so Desktop shows an update. This happens once per version.
- The command saves the Crystalline skill as a zip in Downloads and says where to upload it (Customize > Skills). The routing instructions also tell agents to read the `skills` tool, so Claude in Desktop gets the current skill text with every upgrade, uploaded or not.
- `--no-open` only writes the files. `crystalline uninstall claude-desktop` removes what the install wrote and says where to remove the extension in Claude Desktop.
- `crystalline doctor` warns when the recorded crystalline is gone or too old, when the extension file is missing and when an update is due.
- The extension without a binary inside is gone from the releases page. If you installed it from there, run `crystalline install claude-desktop` once. It replaces the old one. The macOS bundle "Claude Desktop only" with its own binary stays on the releases page.

**Safe upload retries.** An upload through a connected server can take longer than the client waits. The agent was told the server "cannot be reached", although the server had the file. A retry was then refused with "already holds a file".

- An upload onto a path that already holds exactly these bytes writes nothing and answers `unchanged: true`, with or without `overwrite`. Different bytes are still refused.
- A write that was sent and then timed out, or whose connection broke off, now says that it may or may not have happened. It also says how to check: read the path and compare its sha256, or upload the same file again. A failed connect still says "cannot be reached". Reads keep the old wording.
- A write without an answer no longer marks the server as down.

**`write_engram` can guard an overwrite.** It takes the optional `expected_checksum` that `edit_engram`, `split_engram` and `delete_engram` already take. `read_engram` returns the checksum. If the engram changed since your read, the write is refused with the same conflict as `edit_engram`: read again and retry. Without the field, a write works as before. `crystalline write` has `--expected-checksum`.

**Plain reasons for a GitHub link that cannot start.** A person on a deployed instance pressed "Connect GitHub" and saw only "Ask an admin to check the GitHub App." Now a person who is not an admin reads the cause, for example "The GitHub App on this instance has no client secret yet, so it cannot link accounts. Ask an admin to add it." An admin still sees the full sentence with the command that fixes it. The link page an agent hands out follows the same rule.

**The GitHub App card shows the client secret.** For admins the card says "Client secret: set" or "Client secret: not set". When it is not set, the card says that people cannot link their GitHub account and shows the step that fixes it. Before, a missing secret showed only when somebody tried to link.

## Fixes

- In a domain that reviews changes, a share of a draft that started from an older text could overwrite a colleague's newer edit, and nobody was told. We know of no install where it happened, but we cannot rule it out. Now every update merges the team's change into your draft. What does not fit is a conflict: the share of that file waits until you settle it in Fluid or with `crystalline origin resolve` (Keep mine, Take theirs or a merged text). Other files still share.
- When a file under `assets/` was changed in the domain folder and by the team, the conflict could never be settled, and every share of the domain was refused. Keep mine and Take theirs settle it now. Take theirs keeps a copy of the folder's file first.
- Removing an account left its GitHub token behind. A new account under the same name could then write on GitHub with it. A removed account now leaves no token and no grants.
- Two uploads at the same moment to the same new path could both report success, and the second replaced the first. This showed mostly on Windows.
- On macOS and Windows, moving a draft to a name that differs only in letter case hung, and other moves hung with it. A share or a fold of such a move could delete the team's file. Two people's drafts at `Zed.md` and `zed.md` lost one text when both were folded. Now the fold refuses and writes nothing.
- Printing from Safari drew small diagrams across the full column, cut diagrams across pages and left headings alone at the foot of a page. A diagram or a picture now prints at its own size and shrinks only to fit the column and one page. A heading stays with the picture, diagram, code, quote or short table after it. Before long text, a heading keeps room for its first lines.
- In Safari, a dark page with many diagrams stopped drawing for a second or more after it opened. The print copies of the diagrams are now drawn one after the other.
- A table sometimes stayed Markdown source with a read-only preview, until you typed or scrolled. This happened on a busy machine, when the first read of the page stopped before the table. It becomes a grid now.
- With Caps Lock on, Ctrl+Shift+Z on Linux and Windows undid instead of redoing. On Windows a page without co-editing had no Ctrl+Shift+Z redo at all. It redoes now, also in a table cell.
- Something you created, such as an MCP token, did not show in its list when the list was still loading. You saw "No tokens issued yet" until you reloaded. It shows right away now.
- A diagram label written with `#quot;` showed `&quot;` on the reading page. It shows `"` now, and the other entity forms show their character too.
- A table pasted from a web page broke into a paragraph when a cell held code with a backslash before a pipe. The cell keeps its pipe now.
- The refusal for a GitHub link without a client secret named a `crystalline github app set` command that was missing required options. An admin now reads the full command.

## Changes

- In a domain that reviews changes, drafts from before 0.32.0 have no record of the text they started from. Where the team's text differs, such a draft asks you once: you see both texts and choose. Where the team deleted the file, it shows as a conflict too, so a share does not bring the file back without a word. Taking the team's text keeps a copy of yours in the kept texts. You can share other files in the meantime. Leaving review waits until each conflict is settled.
- A new account under a name that still has a removed account's drafts is refused. An admin ends those drafts on the users screen, with `crystalline users discard-drafts <name>` or with `DELETE /api/v1/users/{name}/drafts`, and then adds the account again. A `CRYSTALLINE_ADMIN_NAME` with such drafts is refused the same way: the daemon starts with no admin and the log says why.
- Add an account first, then connect its GitHub identity. A token saved under a name before the account exists is removed when the account is made.
- In the editor Cmd+K (Ctrl+K off a Mac) makes a link. Everywhere else it still opens the command palette. On a Mac, Ctrl+K no longer opens the palette, so in a text field it deletes to the end of the line, as macOS does.
- A label written `&amp;quot;` to show the text `&quot;` now shows `"`. To keep the text `&quot;`, write `#35;quot;`.
- An identical create-only upload over REST now answers 200 with `unchanged: true`, not 412.
- A server older than 0.32 refuses a guarded `write_engram` through a connected domain. It never drops the guard. A write without `expected_checksum` goes through as before.
- The ctl location in `fluid/nginx.conf.template` now waits 180 s instead of 120 s. This changes deployments on the Fluid image. The `/crystalline/` nginx example in `docs/deployment.md` sets 180 s read and send timeouts. If you run your own proxy, keep its timeouts above 120 s too.
- Removing HTML comments from a page now repeats until nothing is left, so two halves can no longer join into a new `<!--`.
- candle is on 0.11.1. This removes the old zip 8.6.0 and closes its five Dependabot alerts. minimatch is pinned to 11.0.4 for the lint tools. zstd and async-executor got their security updates.

## Breaking changes

- On a server with a GitHub App and `github.share_identity` not set, shares now go out as the person who shares. A person with no GitHub link is told to link before a share. A scheduled run in remote mode with an agent account needs a link for that account, or it stops when it takes the lease: add the account, then run `crystalline connect github --personal --as <account>`. To keep the old way, set `github.share_identity` to `instance`.
