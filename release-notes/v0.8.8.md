# Tidy up

A small focused release for snapshot pipelines and daemon disk hygiene.

## New & Noteworthy

- **Every sync and reindex now checkpoints the WAL.** The truncate that previously ran only on `reindex --full` fires after every sync and every reindex, full or incremental. A pipeline that ships `index.db` as a single file - reusing a prior index and reindexing just the delta - no longer needs an external `sqlite3` checkpoint step and can never ship a stale database with its delta stranded in the WAL sidecar.
- **The daemon reclaims its WAL.** A source audit of the embedded engine confirmed WAL growth is bounded on its own (a passive checkpoint fires past a fixed frame threshold and the log restarts once backfilled) but the file is never zeroed. The daemon now truncates it after any background embedding pass that wrote vectors and on graceful shutdown, so a stopped daemon leaves a clean single-file database that is safe to back up or copy.

## Fixes

- Nothing else - this release exists so downstream snapshot builds can drop their checkpoint workarounds.

## Breaking changes

- None.
