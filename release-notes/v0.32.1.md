# Spared no expense.

An idle server on Linux stops working hard for nothing, agents stay signed in and the review findings are fixed.

## New & Noteworthy

**Searches don't wait any more.** Every read went through the one database lock, so a search waited for a sync, a write or another search. The index now opens four read connections beside the writer. A search during a full reindex of 20,000 engrams answers in under a second instead of after the reindex. Set `CRYSTALLINE_READ_CONNECTIONS=0` to turn it off. On a shared Postgres database each instance now holds up to 8 connections instead of 4.

**Writes in large domains are faster.** Every write rebuilt the `index.md` files by reading every file in the domain. Now only changed files are read again. At 20,000 engrams a write spends about 70 ms on it instead of about 600 ms.

**Parallel agent sessions stay signed in.** Two sessions of one MCP client, or a refresh that was retried, could use the same refresh token twice. Crystalline read that as a stolen token and signed the client out, about once a day. Now a token used again within 60 seconds of its rotation gets its own session, at most twice per rotation. A later use, a third use or a use by another client still ends the grant, as before.

- Profile, Connected clients: a "Recently ended" list says for 7 days why a client was signed out.
- Reasons: an old sign-in token was used again, you revoked it, the client signed out, or the password was reset.

**Diagrams stay calm while you type.** Fluid checked and drew a diagram on every key. It now does it once you pause for 200 ms. A single change still draws at once.

## Fixes

- On Linux, `crystalline serve` synced every domain about three times a second while nothing changed. Its own reads of the domain folders woke the file watcher again. On an idle home server that cost 12% of a CPU and about 160 GB of disk writes per day. On Postgres it showed as more than 1,000 commits per second. It is quiet now. macOS was not affected.
- A sync that found no change still wrote to the database. Now it writes nothing. The last sync time is written at most once per hour when nothing changed.
- MCP clients that shared one sign-in were signed out about once a day (see above).
- A password reset left the account's MCP tokens and OAuth grants valid. A reset now ends them.
- Any agent that could read a domain could start a pull from GitHub with `update_domain`. Now only an admin starts a pull. Everybody else who may read the domain gets the reviewers' comments from the last check, and the answer says when that was.
- A web page could reach the JSON API through a DNS name pointing at your server (DNS rebinding) and, for example, create the first admin. `/api/v1` now checks the Host name, as MCP already did.
- The MCP endpoint did not check the Origin header of a browser request. It does now, against the same host list.
- The Fluid image let other sites show the app, `/authorize` included, in a frame. It refuses that now, as the daemon already did.
- On Unix the state folder, the databases and the log were readable by other users, depending on the umask. They are owner-only now, also on an existing install after the first start. A secret file is protected before the secret is written into it.
- Markdown files under `assets/` showed up in `index.md`. They are attachments, so they don't any more.
- A full pass deleted an `index.md` you wrote yourself in a folder without engrams. Only listings Crystalline wrote are removed now.
- During an IME composition, a line that appeared above the editor (a findings alert or a colleague's edit) made the next scroll jump the page by that line's height.
- With a sign-in provider set up, the login form moved up a moment after it showed, when the "Sign in with ..." link arrived. A quick click on Log in could land beside the button. The form stays where it is now.
- On a shared database, two instances that see a domain at different folder paths wrote the path back and forth on every claim.
- `build_context` accepted `timeframe` and ignored it. It now keeps related engrams recorded inside the window. `max_related` is capped at 100.

## Changes

- `/api/v1` answers loopback, the hosts in `service.allowed_hosts` and the host of `service.public_url`. A browser or proxy that reaches the API by another name gets 403. Add that name to `service.allowed_hosts`.
- The compose examples turn on agent sign-in (`CRYSTALLINE_AUTH_MCP=true`). The default of `auth.mcp` did not change. A daemon that listens on the network with agent sign-in off now warns at every start.
- While somebody keeps saving one engram in a shared room, other tabs refresh search at most every 30 seconds.
- `crystalline status` without a running daemon shows the last sync that changed the index, at most an hour old.
- After a downgrade to 0.32.0 or older, OAuth clients sign in again once.
- The `index.md` refresh of one domain runs one at a time, so an older listing can no longer land after a newer one.
- Dependency updates: rmcp 3.9.0 (fixes RUSTSEC-2026-0462) and mermaid 12.3.

## Breaking changes

None. If you open Fluid or the API by a host name that is not loopback and not your `service.public_url` host, add it to `service.allowed_hosts` (see Changes).
