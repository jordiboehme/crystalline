## New & Noteworthy

- **Team knowledge on GitHub.** The big one: a domain can track a GitHub repository. Sign in with a device code (no git, no clones, no token pasting), connect with `domain add --origin`, stay current with `origin update`, share local knowledge as a pull request with `origin share`. A human merges. The agent never does.
- **Three-way merges, honest conflicts.** Upstream changes merge cleanly where possible; real disagreements are recorded as conflicts and settled explicitly with `origin resolve` - mine, theirs or a merged version you supply. Nothing is ever guessed.
- **Six collaboration tools for agents** - `configure`, `add_domain`, `share_changes`, `update_domain`, `origin_status` and `resolve_conflict` - visible only when `github.enabled` is on, so everyone else keeps a lean tool list.
- **A background poller** keeps team domains current on a schedule and reports itself in `status`.
- **Configuration grew up.** A settings registry that knows each value's source, a `configure` tool for agents, `config` verbs for humans and a full environment-variable overlay: team domains, tokens and read-only mode without mounting a config file. Headless machines read their GitHub identity from `CRYSTALLINE_GITHUB_TOKEN`.

## Fixes

- Upstream repository content is treated as hostile input: traversal-shaped paths are rejected at the filesystem chokepoint. Belt, meet suspenders.
- `configure` no longer races a concurrent reader into a half-applied config.

## Breaking changes

None.
