1  What is Crystalline?

You need a function written. Not a hard one: it takes jobs off the retry queue, drops anything older than the cutoff, and hands the rest back to the payments service. So you leave the office, walk down to main street and stop the first person who looks like they might own a laptop.

They are lovely about it. You explain the queue, the cutoff, the payments service; they nod, ask two sharp questions and set to work on a bench outside the bakery. Twenty minutes later they hand you a working implementation. It is clean. It has tests. It is in Haskell.

Your service is in Python. You did not mention that, because why would you? Everybody on your team knows that. The stranger, of course, is not on your team. They met you twenty minutes ago. They do not know that the cutoff is twenty-four hours, that the payments team calls the queue the sin bin, that the last person who touched it left a comment saying DO NOT TOUCH and a wiki page explaining why. They did a good job with what they were given. What they were given was twenty minutes.

That stranger is every fresh session with a language model, and it is the prologue’s waking seen from across the desk. The model is possibly the most capable engineer you have ever put a question to, and you keep meeting it for the first time.

1.1 The new-hire promise

Now imagine hiring the stranger. Not for the afternoon: properly, with a desk. On day one they know nothing about you, the same as before. But on day one you show them where things are. You tell them the service is in Python, that the cutoff is a day, that the queue has a nickname and a history. You let them read the wiki. When they get something wrong in the first week, you do not walk back down to main street and find somebody else; you tell them what was wrong and point them at the page that explains it. By the second month they are correcting you. By the third they are the one writing the wiki page.

That is the entire promise of this book, and it is the promise Crystalline was built to keep: an agent you onboard like a colleague, teach like a colleague and correct like a colleague, and that carries what it learned into the next session, and the one after that. The vocabulary throughout is the vocabulary of a new hire - onboard, teach, learn, capture, recall, evolve - because that is the shape of the thing. The stranger becomes a peer, and the peer keeps getting better.

Nothing about that requires magic. It requires somewhere for what the agent learned to go, a way for it to find that knowledge again when the next task calls for it, and enough discipline in the format that the knowledge stays true as the world moves. That is what Crystalline is.

1.2 What Crystalline is

Crystalline is a single Rust binary that does three jobs. It is a command-line tool for people. It is an MCP server for agents: the Model Context Protocol is the standard by which a harness such as Claude Code, Codex or Claude Desktop hands tools to a model, and Crystalline’s tools are the ones through which an agent searches, reads, captures and refines knowledge. If the letters make you think of Tron’s Master Control Program, relax. This one hands tools out instead of taking them away, and nobody gets de-rezzed. And it is a local search index over a folder of plain markdown files. One download, one binary, no server to deploy and no database to administer.

The files are the point. Knowledge in Crystalline lives in domains: a domain is a folder with a MANIFEST.md at its root that says what the folder covers and when an agent should look there. Inside a domain, each unit of knowledge is an engram: one markdown file with a YAML frontmatter block, holding a title, some prose, a list of observations (a fact, a decision, a gotcha, each as a bullet with a category) and relations to other engrams. Every engram has an address, crystalline://<domain>/<permalink>, that an agent can hand to another agent, or to you. Part II takes each of those words apart properly. For now it is enough to know that everything the agent learns ends up as a file you could open in any editor, diff in any repository and back up with anything.

On top of the files, Crystalline builds what a folder cannot give you on its own: routing, so an agent knows which domain owns a task without reading every file; full-text and semantic search, so a question phrased differently from the answer still finds it; a knowledge graph, so related engrams pull each other in; and a temporal model, so a fact that stopped being true in March is still there, still dated and no longer mistaken for the present. The index that powers all of that is a derived layer. Delete it and it is rebuilt from the files. The files are the truth, and nothing else is.

An engram, by the way, is neuroscience’s word for the physical trace an experience leaves in a brain. Crystalline borrowed it because that is what one is: the trace a session leaves behind, in a form the next session can pick up.

1.3 What Crystalline is not

It is not a notes app. The primary author in Crystalline is the agent, capturing what it learned as a byproduct of the work; you take part, correct and add, but you are not the one doing the filing. A notes app is a place a person writes for a person. Crystalline is a place an agent writes so that an agent can act.

It is not a wiki, either, though it can hold most of what a wiki holds. A wiki is read by people, who bring their own judgment about what is current, what is relevant and which of two contradictory pages to trust. An agent reading a wiki has to be handed that judgment. Crystalline is built for a reader that acts on what it finds: every engram carries a status, a place for the dates that bound it and a record of who wrote it and when, because a reader that acts needs to know whether the fact in front of it still holds.

And it is not a retrieval pipeline dressed up as a product. A vector index will find text that resembles a question. It does not know which domain owns a task, that a fact was superseded in March, who verified a claim or that something worth writing down just happened in this session. Crystalline treats similarity as one ranking signal inside a larger system of routing, provenance and time, on files you own, with nothing to operate.

1.4 How teams end up here

Most teams that arrive here walked the same road, and it is worth walking it once, because every step on it is reasonable.

It begins with one markdown file of instructions for the agent. Conventions, the layout of the repository, the three things it keeps getting wrong. This works, and it works well, right up to the day the file grows past what fits comfortably in a session’s context. So the file becomes a folder of files, one per topic, and the agent is told to read the relevant one. This also works, until nobody, human or agent, can say which file is the relevant one for a given task, and the agent starts reading all of them, or none.

So index files appear: a README that points at folders, folders with their own README pointing at files. Now a lookup is a walk down a tree of pointers, and keeping the pointers accurate quietly becomes a job that nobody was hired for. Every rung of this ladder scales further than the one before it, and every rung breaks somewhere in the hundreds of files. You have, by this point, hand-built a filesystem on top of a filesystem, and it is exactly as much fun to maintain as that sounds.

When knowledge reaches the thousands of units, reading and pointer-walking stop being viable at all, and what is needed is what every large body of knowledge has ever needed: real indexes. That is the rung Crystalline is. It keeps the plain markdown - readable, and still yours - and adds domain routing, hybrid search, a graph and temporal filtering on top, so that the ten-thousandth engram is exactly as findable as the tenth.

1.5 The two halves

Crystalline has a second face, and it is the one for people. The binary serves a web UI called Fluid, on by default at http://localhost:7411, on the same daemon your agents already talk to. There is nothing to deploy. The first visit creates your admin account in the browser, and from then on you can read what your agent learned, fix a fact it got slightly wrong or add something of your own, without going through the model and without spending a token on it.

The split is deliberate and it runs through the whole book. Crystalline stores what was learned. Fluid is where you read, edit and think with it: an engram as a page with its details in a rail down the side, an editor with live preview, a search across everything, a graph of what connects to what, and a maintenance page listing what the knowledge needs next. What you write there does not sit unreviewed; the agent’s next maintenance pass verifies it, aligns the tags and wires it into the graph. The next chapter explains why the UI carries that name. The short version is that a person and a model are the same kind of mind, and Fluid is the room where both of them meet what has been learned.

1.6 Where it runs

Crystalline is not a hosted service. Nobody’s servers are involved: the binary runs on a machine of yours, the knowledge is a folder on its disk and the index sits beside it. GitHub, when a team uses it, holds a copy of a domain’s files for review and sync, the way it holds code. It never serves the knowledge and never sees the index. So the question is not whether to host but where the one daemon runs, and there are two answers.

On your laptop is the default, and it is where Crystalline does the most. The install wires your harness with the session-start briefing, the capture nudge and the skills, and a domain’s tools provision straight into it. Everything the agent knows is on your disk, readable in Fluid with no agent and no network. A shared instance, one daemon on a machine the team runs, is for the things a laptop cannot do. People who never open a terminal read and correct knowledge in the browser. Several people edit one engram in a meeting. Agents with no harness of their own, a hosted runner or a chat client, reach it over HTTP. Either way a domain can live in a GitHub repository and travel between instances as reviewed proposals. Start on the laptop; chapter 7 names the moment to move.

Shape Who connects What it gives you
Your laptop your harness and your browser the full install: briefing, nudges, skills and tools wired into the harness; knowledge on your disk, readable offline
A shared instance the team’s agents over HTTP, everyone’s browser one truth for the whole team, accounts, co-editing, agents and people with no harness
A team domain any instance, laptop or shared review before knowledge reaches anyone else; the domain travels between instances through GitHub
NoteIn practice

Ripley is a platform engineer at Tyrell, a freight-forwarding startup with nine engineers and one payments service that everybody is a little afraid of. On a Monday in March she asks her agent to add a metric to the retry queue. She explains the queue, the twenty-four-hour cutoff and why the cutoff is twenty-four hours (a chargeback rule at Encom, the bank, nothing to do with the code). The agent does the work, does it well and the session ends. On Tuesday a colleague asks the same agent to change the alerting on the same queue, and starts by explaining the queue, the cutoff and the bank. On Thursday Ripley does it a third time, and catches herself typing the sentence about the chargeback rule, word for word, into a chat window, for the third time that week.

With Crystalline, Monday ends differently. Before the session closes, the agent proposes capturing what it learned: the cutoff, the reason for it and the name the team uses for the queue, filed as an engram in the team’s engineering domain with the bank rule as a fact and the chargeback window as the reason. Ripley says yes. On Tuesday her colleague asks about the alerting, and the agent, onboarded at session start with one line telling it where engineering knowledge lives, searches that domain first, recalls the engram and starts from the cutoff rather than from zero. On Thursday nobody explains anything. The stranger on main street was never the problem. The problem was that the team kept going back to main street.

NoteIn brief

A fresh session with a language model is a brilliant stranger: capable of anything, told nothing, gone by tomorrow. Crystalline is a single Rust binary - a CLI for people, an MCP server for agents and a search index over plain markdown - that gives an agent somewhere for what it learns to go and a way to find it again, so it can be onboarded, taught and corrected like a colleague. The files are the source of truth and the index is disposable. Fluid, the web UI on the same daemon, is the half for people. What it holds is knowledge for an agent to act on, which makes it neither a notes app nor a wiki. It runs on your laptop or on one machine your team operates, never as a hosted service, and GitHub is the review layer either shape can use.
